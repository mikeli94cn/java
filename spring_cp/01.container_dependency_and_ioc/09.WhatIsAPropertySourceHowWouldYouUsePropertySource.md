# What is a Property Source? How would you use `@PropertySource`?

This topic is about **how Spring loads external configuration values** into your application.

It connects with:

```text
ApplicationContext
        ↓
Environment
        ↓
Property Sources
        ↓
@Configuration / @Value / @Bean
```

The key idea:

> **A property source is a location where Spring can read configuration properties (key-value pairs).**

Examples:

```properties
database.url=jdbc:mysql://localhost:3306/mydb
database.username=root
database.password=123456
```

Spring can load these values from different places and make them available to Beans.

---

# 1. What is a Property Source?

A **property source** is a source of configuration properties.

A property is simply:

```text
key = value
```

Example:

```properties
app.name=MyApplication
server.port=8080
```

The key:

```text
app.name
```

has the value:

```text
MyApplication
```

Spring represents these properties internally through the `Environment` abstraction.

Conceptually:

```text
                 ApplicationContext
                         |
                         ↓
                  Environment
                         |
             +-----------+-----------+
             |                       |
             ↓                       ↓
     PropertySource 1          PropertySource 2
     application.properties   Environment variables
```

---

# 2. Common property sources in Spring

Spring can read properties from many places.

## 1. Application properties

Most common:

```
application.properties
```

Example:

```properties
server.port=8080
app.name=OrderService
```

Spring Boot automatically loads this.

---

## 2. YAML files

Example:

```
application.yml
```

```yaml
server:
  port: 8080

app:
  name: OrderService
```

---

## 3. Environment variables

Example:

Linux:

```bash
export DB_URL=mysql://localhost/mydb
```

Spring can access:

```text
DB_URL
```

---

## 4. Command-line arguments

Example:

```bash
java -jar app.jar --server.port=9090
```

---

## 5. Custom property files

Example:

```
database.properties
```

```properties
db.url=localhost
db.username=root
```

This is where `@PropertySource` is useful.

---

# 3. What is `@PropertySource`?

`@PropertySource` tells Spring:

> "Load this external properties file into the Spring Environment."

It is used on a configuration class.

Example:

```java
@Configuration
@PropertySource("classpath:database.properties")
public class AppConfig {

}
```

Now Spring loads:

```
database.properties
```

into the `Environment`.

---

# 4. Example using `@PropertySource`

Suppose we have:

```
src/main/resources/database.properties
```

Content:

```properties
db.url=jdbc:mysql://localhost:3306/test
db.username=root
db.password=password123
```

Configuration:

```java
@Configuration
@PropertySource("classpath:database.properties")
public class AppConfig {

}
```

Now Spring knows these properties exist.

---

# 5. Using properties with `@Value`

The simplest way to read a property is `@Value`.

Example:

```java
@Component
public class DatabaseConfig {

    @Value("${db.url}")
    private String url;

    @Value("${db.username}")
    private String username;


    public void print() {
        System.out.println(url);
        System.out.println(username);
    }
}
```

Spring replaces:

```java
"${db.url}"
```

with:

```text
jdbc:mysql://localhost:3306/test
```

The flow:

```text
database.properties
        |
        ↓
@PropertySource
        |
        ↓
Spring Environment
        |
        ↓
@Value("${db.url}")
        |
        ↓
Java field
```

---

# 6. How does Spring resolve `${...}`?

When Spring sees:

```java
@Value("${db.username}")
private String username;
```

it looks for:

```text
db.username
```

inside its property sources.

Conceptually:

```text
@Value("${db.username}")
              |
              ↓
        Environment
              |
              ↓
     search PropertySources
              |
              ↓
       db.username=root
```

---

# 7. Using `Environment`

Instead of `@Value`, you can directly access properties.

Example:

```java
@Component
public class DatabaseConfig {

    private final Environment environment;


    public DatabaseConfig(Environment environment) {
        this.environment = environment;
    }


    public void print() {

        String url =
            environment.getProperty("db.url");

        System.out.println(url);
    }
}
```

The `Environment` is provided by the `ApplicationContext`.

Relationship:

```text
ApplicationContext
        |
        ↓
Environment
        |
        ↓
getProperty()
```

# 8. `@PropertySource` and `ApplicationContext`

Remember your previous topic:

```text
ApplicationContext
        ↓
creates Beans
        ↓
injects dependencies
```

`@PropertySource` affects the context configuration.

Example:

```java
@Configuration
@PropertySource("classpath:app.properties")
@ComponentScan("com.example")
public class AppConfig {

}
```

When the context starts:

```text
ApplicationContext starts
        ↓
Read AppConfig
        ↓
Load app.properties
        ↓
Register properties
        ↓
Create Beans
        ↓
Inject values
```

# 9. Using multiple property files

You can specify multiple sources:

```java
@Configuration
@PropertySource({
    "classpath:database.properties",
    "classpath:security.properties"
})
public class AppConfig {

}
```

Spring loads:

```
database.properties
security.properties
```

Both become available.

---

# 10. Ignoring missing property files

By default:

```java
@PropertySource("classpath:missing.properties")
```

If the file does not exist:

```text
Application startup fails
```

You can make it optional:

```java
@Configuration
@PropertySource(
    value = "classpath:optional.properties",
    ignoreResourceNotFound = true
)
public class AppConfig {

}
```

Now:

```text
File exists  → load it
File missing → continue
```

# 11. Property precedence

Spring can have many property sources:

```text
Command line arguments
        ↑
Environment variables
        ↑
application.properties
        ↑
@PropertySource
```

If the same property exists in multiple places:

```properties
server.port=8080
```

and:

```bash
--server.port=9090
```

Spring uses the higher-priority value.

Conceptually:

```text
High priority
      |
      ↓
Command line
Environment variables
application.properties
@PropertySource
      |
      ↓
Low priority
```

# 12. `@PropertySource` vs Spring Boot configuration

This is an important exam point.

In Spring Boot, you usually use:

```
application.properties
```

or:

```
application.yml
```

Example:

```properties
spring.datasource.url=jdbc:mysql://localhost/db
```

You usually do **not** need:

```java
@PropertySource("classpath:application.properties")
```

because Spring Boot loads it automatically.

Good use cases:


### 2. Library configuration

A reusable library may provide:


### 3. Separating configuration

Example:


# 14. `@PropertySource` with `@ConfigurationProperties`

In modern Spring Boot applications, a more common approach is:

```java
@ConfigurationProperties(prefix="database")
public class DatabaseProperties {

    private String url;

    private String username;

}
```

Properties:

```properties
database.url=localhost
database.username=root
```

Spring automatically maps:

```text
database.url
        ↓
DatabaseProperties.url
```

This is often preferred for larger configurations.

---

# 15. `@Value` vs `@ConfigurationProperties`

Another common interview topic.

## `@Value`

Good for a few values:

```java
@Value("${server.port}")
private int port;
```

---

## `@ConfigurationProperties`

Better for groups of properties:

```java
@ConfigurationProperties(prefix="database")
public class DatabaseProperties {

    private String url;
    private String username;
    private String password;

}
```

Comparison:

|                             | `@Value` | `@ConfigurationProperties` |
| --------------------------- | -------- | -------------------------- |
| Small number of values      | ✅        |                            |
| Large configuration objects |          | ✅                          |
| Type-safe                   | Limited  | Better                     |
| Validation support          | Limited  | Better                     |

```
        |
```

```text
        |
        ↓

```

# 17. Exam-ready answer

Question:

> **What is a property source? How would you use `@PropertySource`?**

A good answer:

> **A property source is a location from which Spring reads configuration properties, such as a properties file, environment variables, or command-line arguments. Spring stores these properties in the `Environment`. The `@PropertySource` annotation can be placed on a `@Configuration` class to add a custom properties file to the Spring Environment. For example:**
>
> ```java
> @Configuration
> @PropertySource("classpath:database.properties")
> public class AppConfig {
> }
> ```
>
> **The properties can then be injected using `@Value` or accessed through the `Environment` object.**

# 18. Key points to memorize

```text
Property Source
        ↓
source of key=value configuration

@PropertySource
        ↓
load custom properties file

Environment
        ↓
stores property values

@Value("${property}")
        ↓
inject value into Bean
```

The one-line interview answer:

> **A property source is a source of configuration values available to Spring's Environment. `@PropertySource` adds a custom properties file to the Environment so that values can be injected into Beans using `@Value` or accessed through `Environment`.**
