# What is the behavior of the annotation `@Autowired` with regards to field injection, constructor injection and method injection?

This topic is about **Dependency Injection (DI)** in Spring and how the `@Autowired` annotation tells Spring where and how to inject dependencies.

The key idea:

> **`@Autowired` asks Spring to find a matching Bean from the `ApplicationContext` and inject it into a class. It can be applied to fields, constructors, and methods.**

The three injection styles are:

1. **Field injection**
2. **Constructor injection**
3. **Method (setter) injection**



# 1. What does `@Autowired` do?

Suppose we have:

```java
@Repository
public class UserRepository {

}
```

and:

```java
@Service
public class UserService {

}
```

`UserService` depends on `UserRepository`:

```java
@Service
public class UserService {

    private UserRepository repository;

}
```

Spring needs to provide:

```java
new UserRepository()
```

to:

```java
UserService
```

This is dependency injection.

The process:

```text
ApplicationContext

      |
      ↓

Find UserRepository Bean

      |
      ↓

Inject into UserService

      |
      ↓

UserService can use it
```

---

# 2. Field injection

## Example

```java
@Service
public class UserService {

    @Autowired
    private UserRepository repository;

}
```

Spring sees:

```java
@Autowired
private UserRepository repository;
```

and performs:

```text
Create UserService
        |
        ↓
Find UserRepository Bean
        |
        ↓
Set private field
        |
        ↓
UserService ready
```

Conceptually:

```java
UserService service = new UserService();

service.repository = userRepository;
```

---

# 3. How does field injection work internally?

The Bean lifecycle is approximately:

```text
1. Create object

       ↓

2. Inject dependencies

       ↓

3. Call initialization methods

       ↓

4. Bean ready
```

Example:

```java
@Service
public class UserService {

    @Autowired
    private UserRepository repository;


    @PostConstruct
    public void init() {
        System.out.println(repository);
    }
}
```

When `init()` runs:

```text
repository is already injected
```

---

# 4. Advantages of field injection

### Less code

Example:

```java
@Autowired
private UserRepository repository;
```

No constructor required.

---

### Easy for small examples

Many tutorials use it because it is simple.

---

# 5. Disadvantages of field injection

However, field injection is generally **not recommended** in modern Spring applications.

## Problem 1: Cannot create immutable objects

Example:

```java
@Service
public class UserService {

    @Autowired
    private UserRepository repository;

}
```

The field cannot be:

```java
private final UserRepository repository;
```

because Spring injects after object creation.

---

## Problem 2: Harder to test

Example:

```java
UserService service =
        new UserService();
```

Now:

```text
repository is null
```

You must use reflection or Spring test support.

---

## Problem 3: Hides dependencies

The class does not clearly show:

```text
"I need UserRepository"
```

from its constructor.

---

# 6. Constructor injection

Constructor injection is the preferred approach.

Example:

```java
@Service
public class UserService {

    private final UserRepository repository;


    @Autowired
    public UserService(UserRepository repository) {
        this.repository = repository;
    }

}
```

The dependency is provided when the object is created.

Conceptually:

```java
UserRepository repo = new UserRepository();

UserService service =
        new UserService(repo);
```

---

# 7. Why constructor injection is preferred

## 1. Dependencies are explicit

The constructor shows:

```java
public UserService(UserRepository repository)
```

means:

```text
UserService requires UserRepository
```

---

## 2. Supports immutability

You can write:

```java
private final UserRepository repository;
```

The reference cannot change.

---

## 3. Easier unit testing

You can simply do:

```java
UserRepository mock =
        new MockUserRepository();

UserService service =
        new UserService(mock);
```

No Spring container needed.

---

# 8. Do you need `@Autowired` on constructors?

Important Spring interview point.

Before Spring 4.3:

```java
@Autowired
public UserService(UserRepository repository) {

}
```

was required.

Since Spring 4.3:

If a class has only one constructor:

```java
@Service
public class UserService {


    private final UserRepository repository;


    public UserService(UserRepository repository) {
        this.repository = repository;
    }
}
```

`@Autowired` is optional.

Spring automatically uses that constructor.

---

# 9. Multiple constructors

Suppose:

```java
@Service
public class UserService {


    public UserService() {

    }


    public UserService(UserRepository repository) {

    }
}
```

Now Spring does not know which constructor to use.

You need:

```java
@Autowired
public UserService(UserRepository repository) {

}
```

Now Spring knows:

```text
Use this constructor
```

---

# 10. Method injection

`@Autowired` can also be placed on methods.

Example:

```java
@Service
public class UserService {


    private UserRepository repository;


    @Autowired
    public void setRepository(
            UserRepository repository) {

        this.repository = repository;
    }

}
```

This is similar to setter injection.

The lifecycle:

```text
Create UserService

        ↓

Call setRepository()

        ↓

Inject UserRepository

        ↓

Bean ready
```

---

# 11. Why use method injection?

Method injection is useful when:

## 1. You want custom injection logic

Example:

```java
@Autowired
public void configure(
        UserRepository repository,
        EmailService emailService) {

    this.repository = repository;
    this.emailService = emailService;
}
```

One method can inject multiple dependencies.

---

## 2. Optional dependencies

Example:

```java
@Autowired(required = false)
public void setCache(Cache cache) {

}
```

If no Cache Bean exists:

```text
continue without injection
```

---

# 12. Comparison of three injection styles

|                         | Field Injection | Constructor Injection | Method Injection |
| ----------------------- | --------------- | --------------------- | ---------------- |
| Where `@Autowired` goes | Field           | Constructor           | Method           |
| Recommended?            | ❌ Usually no    | ✅ Yes                 | Sometimes        |
| Supports `final` fields | ❌ No            | ✅ Yes                 | ❌ No             |
| Easy testing            | Poor            | Excellent             | Good             |
| Dependencies visible    | No              | Yes                   | Yes              |
| Immutable object        | No              | Yes                   | No               |

---

# 13. Injection order in Bean lifecycle

For a normal Spring Bean:

```text
1. Constructor called

        ↓

2. Object created

        ↓

3. Field injection

        ↓

4. Setter/method injection

        ↓

5. @PostConstruct

        ↓

6. BeanPostProcessor

        ↓

7. Bean ready
```

Example:

```java
@Service
public class UserService {


    @Autowired
    private UserRepository repository;


    @Autowired
    public void setLogger(Logger logger){

    }


    @PostConstruct
    public void init(){

    }
}
```

Order:

```text
Constructor

↓

@Autowired field

↓

@Autowired method

↓

@PostConstruct
```

---

# 14. How does Spring find the Bean?

`@Autowired` uses type matching.

Example:

```java
@Autowired
private UserRepository repository;
```

Spring searches:

```text
ApplicationContext
        |
        ↓
Beans of type UserRepository
```

If exactly one exists:

```text
Inject it
```

---

# 15. What if multiple Beans exist?

Example:

```java
@Repository
class MysqlUserRepository
        implements UserRepository {

}


@Repository
class OracleUserRepository
        implements UserRepository {

}
```

Now:

```java
@Autowired
private UserRepository repository;
```

has two candidates.

Spring throws:

```text
NoUniqueBeanDefinitionException
```

---

## Solution 1: `@Primary`

```java
@Primary
@Repository
class MysqlUserRepository
        implements UserRepository {

}
```

Spring chooses it.

---

## Solution 2: `@Qualifier`

```java
@Autowired
@Qualifier("oracleUserRepository")
private UserRepository repository;
```

Specify the exact Bean.

---

# 16. `@Autowired` vs `@Resource`

Another interview topic.

`@Autowired`:

* Spring annotation
* primarily type-based injection

Example:

```java
@Autowired
UserRepository repository;
```

---

`@Resource`:

* Java/Jakarta annotation
* primarily name-based injection

Example:

```java
@Resource(name="userRepository")
UserRepository repository;
```

---

# 17. Relationship with IoC

Without Spring:

```java
public class UserService {

    UserRepository repo =
        new UserRepository();

}
```

The class controls creation.

---

With Spring:

```java
@Service
public class UserService {

    public UserService(
        UserRepository repo) {

    }
}
```

Spring controls creation.

This is:

```text
Inversion of Control
```

# 18. Exam-ready answer

Question:

> **What is the behavior of the annotation `@Autowired` with regards to field injection, constructor injection and method injection?**

A strong answer:

> **`@Autowired` tells Spring to resolve and inject a dependency from the ApplicationContext. It can be applied to fields, constructors, and methods. Field injection injects the dependency directly into a field after object creation, but it is generally discouraged because it makes testing harder and prevents immutability. Constructor injection provides dependencies through the constructor and is the recommended approach because dependencies are explicit and objects can be immutable. Method injection allows Spring to call a setter or configuration method to provide dependencies. `@Autowired` is processed during Bean creation after instantiation but before initialization callbacks such as `@PostConstruct`.**

---

# 19. The short version to memorize

```text
@Autowired

Field:
    inject after object creation
    simple but not recommended


Constructor:
    dependency provided during creation
    recommended


Method:
    Spring calls method to inject dependency
    useful for multiple or optional dependencies
```

Modern Spring best practice:

```java
@Service
public class UserService {

    private final UserRepository repository;


    public UserService(UserRepository repository) {
        this.repository = repository;
    }
}
```

**Prefer constructor injection.** It aligns best with Spring's IoC philosophy and clean object-oriented design.
