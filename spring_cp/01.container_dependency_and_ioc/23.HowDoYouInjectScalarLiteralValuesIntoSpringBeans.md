# How do you inject scalar/literal values into Spring Beans?

So far we've talked about injecting **objects** into Spring Beans:

```java
@Service
public class OrderService {

    private final PaymentService paymentService;

    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
}
```

Here `PaymentService` is a **dependency object**.

But a Spring Bean may also need simple values such as:

```text
String
int
long
double
boolean
URL
Duration
...
```

These are often called **scalar values**, **literal values**, or **configuration properties**.

For example:

```java
@Service
public class EmailService {

    private String host = "smtp.example.com";
    private int port = 587;
    private boolean enabled = true;
}
```

Instead of hard-coding these values, Spring can inject them.

---

# 1. The simplest way: `@Value`

The most basic Spring mechanism is `@Value`.

```java
@Component
public class EmailService {

    @Value("smtp.example.com")
    private String host;

    @Value("587")
    private int port;

    @Value("true")
    private boolean enabled;
}
```

Spring injects:

```text
"smtp.example.com" → String host
"587"              → int port
"true"             → boolean enabled
```

Spring performs the necessary type conversion.

---

# 2. Literal value vs property value

There are two important forms.

### Literal value

```java
@Value("Hello")
private String message;
```

This literally injects:

```text
Hello
```

### Property placeholder

More commonly:

```java
@Value("${app.name}")
private String appName;
```

Then:

```properties
app.name=MyApplication
```

Spring reads:

```text
app.name
    ↓
MyApplication
    ↓
@Value("${app.name}")
    ↓
appName
```

This is much more useful because you don't hard-code configuration into Java code.

---

# 3. Example with `application.properties`

Suppose:

```properties
app.name=Order System
app.port=8080
app.enabled=true
```

Then:

```java
@Component
public class AppConfig {

    @Value("${app.name}")
    private String name;

    @Value("${app.port}")
    private int port;

    @Value("${app.enabled}")
    private boolean enabled;

    public void print() {
        System.out.println(name);
        System.out.println(port);
        System.out.println(enabled);
    }
}
```

Output:

```text
Order System
8080
true
```

The important syntax is:

```java
@Value("${property.name}")
```

The `${...}` means:

> Resolve this value from Spring's property sources.

---

# 4. You can use `@Value` with constructor injection

For modern Spring code, constructor injection is generally preferable to field injection.

Instead of:

```java
@Component
public class AppConfig {

    @Value("${app.name}")
    private String name;
}
```

you can write:

```java
@Component
public class AppConfig {

    private final String name;
    private final int port;

    public AppConfig(
            @Value("${app.name}") String name,
            @Value("${app.port}") int port) {

        this.name = name;
        this.port = port;
    }
}
```

This gives you:

```text
Spring
  │
  ├── app.name → String
  │
  └── app.port → int
            ↓
       Constructor
            ↓
        AppConfig
```

This is particularly nice because the fields can be `final`.

---

# 5. Default values

What happens if the property doesn't exist?

You can specify a default:

```java
@Value("${app.port:8080}")
private int port;
```

Meaning:

```text
app.port exists?
       │
   ┌───┴───┐
  yes      no
   │        │
   ↓        ↓
 use it   8080
```

For example:

```java
@Value("${app.name:My Application}")
private String name;
```

If `app.name` isn't configured:

```text
name = "My Application"
```

This is very useful for optional configuration.

# 6. Injecting different scalar types

Spring can convert property strings into many common Java types.

### String

```java
@Value("${app.name}")
private String name;
```

### int

```java
@Value("${app.port}")
private int port;
```

### long

```java
@Value("${app.timeout}")
private long timeout;
```

### boolean

```java
@Value("${app.enabled}")
private boolean enabled;
```

### double

```java
@Value("${app.rate}")
private double rate;
```

For example:

```properties
app.port=8080
app.timeout=5000
app.enabled=true
app.rate=0.75
```

Spring performs the conversions.

---

# 7. Injecting lists

You can also inject collections.

For example:

```properties
app.servers=server1,server2,server3
```

Then:

```java
@Value("${app.servers}")
private List<String> servers;
```

Conceptually:

```text
"server1,server2,server3"
             ↓
        type conversion
             ↓
["server1", "server2", "server3"]
```

You can also use SpEL for more complicated expressions.

---

# 8. SpEL and `@Value`

`@Value` isn't limited to property placeholders.

It also supports **Spring Expression Language (SpEL)**.

For example:

```java
@Value("#{2 + 3}")
private int number;
```

The result is:

```text
number = 5
```

Or:

```java
@Value("#{systemProperties['user.home']}")
private String home;
```

So `@Value` can work with:

```text
literal values
       +
property placeholders
       +
SpEL expressions
```

# 9. Property sources

Where does:

```java
@Value("${app.name}")
```

actually get the value?

Spring has an `Environment` containing **property sources**.

Conceptually:

```text
                  Spring Environment
                         │
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
 application.properties  Environment    System properties
        │                 variables
        └────────────────┼────────────────┘
                         ↓
                    app.name
                         ↓
               @Value("${app.name}")
                         ↓
                       Bean
```

Spring Boot supports many configuration sources, including:

* `application.properties`
* `application.yml`
* profile-specific properties
* environment variables
* JVM system properties
* command-line arguments
* other configured property sources

This connects directly with the previous topic we discussed: **Property Sources**.

# 10. `@Value` vs `@ConfigurationProperties`

For a few individual values, `@Value` is convenient:

```java
@Value("${app.name}")
private String name;

@Value("${app.port}")
private int port;
```

But imagine you have:

```properties
app.name=Order System
app.version=1.0
app.port=8080
app.timeout=5000
app.enabled=true
```

Using many `@Value` annotations can become messy.

Spring Boot provides:

```java
@ConfigurationProperties
```

For example:

```java
@ConfigurationProperties(prefix = "app")
public class AppProperties {

    private String name;
    private String version;
    private int port;
    private long timeout;
    private boolean enabled;

    // getters and setters
}
```

Then:

```text
app.name       → name
app.version    → version
app.port       → port
app.timeout    → timeout
app.enabled    → enabled
```

This is generally better for **groups of related configuration properties**.

---

# 11. `@Value` vs `@ConfigurationProperties`

A useful interview comparison:

| Feature                        | `@Value`        | `@ConfigurationProperties` |
| ------------------------------ | --------------- | -------------------------- |
| Single value                   | Excellent       | Overkill                   |
| Several related values         | Possible        | Better                     |
| Structured configuration       | Limited         | Excellent                  |
| Type-safe configuration object | Less convenient | Excellent                  |
| Validation                     | Limited         | Strong support             |
| SpEL                           | Yes             | No                         |
| Simple usage                   | Very easy       | More setup                 |

For example:

### Small configuration

```java
@Value("${server.port}")
private int port;
```

Good.

### Large configuration

```properties
database.url=...
database.username=...
database.password=...
database.pool-size=20
database.timeout=5000
```

A configuration class is cleaner:

```java
@ConfigurationProperties(prefix = "database")
public class DatabaseProperties {

    private String url;
    private String username;
    private String password;
    private int poolSize;
    private long timeout;
}
```

# 12. Scalar injection vs Dependency Injection

This is an important conceptual distinction.

Earlier we had:

```java
public OrderService(PaymentService paymentService)
```

That's **object dependency injection**.

Now:

```java
public OrderService(
        @Value("${app.currency}") String currency) {
}
```

That's **configuration/scalar value injection**.

So Spring can provide both:

```text
                   Spring IoC Container
                           │
             ┌─────────────┴─────────────┐
             ↓                           ↓
       Object dependency            Scalar value
             │                           │
      PaymentService                String currency
             │                           │
             └─────────────┬─────────────┘
                           ↓
                     OrderService
```

For example:

```java
@Service
public class OrderService {

    private final PaymentService paymentService;
    private final String currency;

    public OrderService(
            PaymentService paymentService,
            @Value("${app.currency}") String currency) {

        this.paymentService = paymentService;
        this.currency = currency;
    }
}
```

Now Spring provides **both kinds of dependencies**.

# 13. How this fits into the Spring concepts you've been learning

You can now see a larger picture:

```text
                    Spring IoC Container
                           │
             ┌─────────────┴─────────────┐
             │                           │
       Bean creation                Configuration
             │                           │
             ↓                           ↓
       Object dependencies         Property Sources
             │                           │
             ↓                           ↓
            DI                       Environment
             │                           │
             └─────────────┬─────────────┘
                           ↓
                    @Value / @ConfigurationProperties
                           ↓
                         Bean
```

So there are really two common things Spring injects:

```text
1. Objects
   PaymentService
   UserRepository
   OrderRepository
   ...

2. Configuration values
   String
   int
   boolean
   URL
   Duration
   ...
```

## Exam-ready answer

> **Scalar or literal values can be injected into Spring Beans using `@Value`. `@Value` can inject literal values, property values from Spring's `Environment`, and SpEL expressions. For example, `@Value("${app.port}")` injects the `app.port` configuration property into a Bean. For groups of related configuration properties, Spring Boot's `@ConfigurationProperties` is generally more suitable.**

### Short version to memorize

```text
How do you inject scalar/literal values?

        @Value
          │
          ├── literal
          │     @Value("8080")
          │
          ├── property
          │     @Value("${app.port}")
          │
          └── SpEL
                @Value("#{2 + 3}")

For many related properties:
        ↓
@ConfigurationProperties
```

**The key distinction:** `@Autowired` is mainly about **injecting Beans/objects**, while `@Value` is mainly about **injecting configuration/scalar values**.
