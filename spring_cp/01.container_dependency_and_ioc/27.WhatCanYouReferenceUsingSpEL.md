# What can you reference using SpEL (Spring Expression Language)?

This topic asks:

> **What kinds of objects, values, and structures can Spring Expression Language access or reference?**

The short answer:

> **SpEL can reference properties, methods, Beans in the Spring container, system properties, variables, collections, types, and other objects available in the evaluation context.**

SpEL is much more powerful than just arithmetic.

The general syntax is:

```java
#{ expression }
```

Example:

```java
@Value("#{2 + 3}")
private int result;
```

Spring evaluates:

```text
2 + 3 → 5
```

---

# 1. Reference literal values

SpEL can directly use literals.

## String

```java
@Value("#{'Hello Spring'}")
private String message;
```

Result:

```text
Hello Spring
```

---

## Numbers

```java
@Value("#{100}")
private int number;
```

Result:

```text
100
```

---

## Boolean

```java
@Value("#{true}")
private boolean enabled;
```

Result:

```text
true
```

---

# 2. Reference properties of objects

SpEL can access object properties using the property name.

Suppose:

```java
@Component("user")
public class User {

    private String name = "Mike";

    public String getName() {
        return name;
    }
}
```

You can write:

```java
@Value("#{user.name}")
private String username;
```

Spring does:

```text
user.name
    ↓
getName()
    ↓
"Mike"
```

So SpEL supports:

```text
object.property
```

---

# 3. Reference Spring Beans

This is one of the most important SpEL features.

Suppose:

```java
@Component("databaseConfig")
public class DatabaseConfig {

    public String getUrl() {
        return "jdbc:mysql://localhost/db";
    }
}
```

Another bean:

```java
@Component
public class ApplicationInfo {

    @Value("#{databaseConfig.url}")
    private String url;
}
```

SpEL looks up:

```text
databaseConfig
        ↓
Spring Bean
        ↓
getUrl()
        ↓
jdbc:mysql://localhost/db
```

So:

```text
#{beanName.property}
```

means:

> Find a Bean in the ApplicationContext and access it.

---

# 4. Reference Bean methods

SpEL can call methods.

Example:

```java
@Component("calculator")
public class Calculator {

    public int add(int a, int b) {
        return a + b;
    }
}
```

Use:

```java
@Value("#{calculator.add(10,20)}")
private int result;
```

Result:

```text
30
```

The syntax:

```text
#{beanName.method(arguments)}
```

---

# 5. Reference system properties

SpEL can access JVM system properties.

Example:

```java
@Value("#{systemProperties['java.version']}")
private String javaVersion;
```

The value comes from:

```java
System.getProperty("java.version")
```

Other examples:

```java
@Value("#{systemProperties['user.home']}")
private String home;
```

Possible result:

```text
/home/mike
```

---

# 6. Reference environment variables

SpEL can access environment variables.

Example:

```java
@Value("#{systemEnvironment['PATH']}")
private String path;
```

This reads:

```bash
echo $PATH
```

Conceptually:

```text
systemEnvironment
        ↓
Operating system environment variables
```

---

# 7. Reference other variables

SpEL supports variables.

Example:

```java
EvaluationContext context;
context.setVariable("name", "Spring");
```

Then:

```java
#name
```

returns:

```text
Spring
```

The `#` prefix means:

> This is a SpEL variable.

Example:

```java
@Value("#{'Hello ' + #name}")
private String message;
```

---

# 8. Reference types (static fields and methods)

SpEL can reference Java classes using:

```text
T(Type)
```

Example:

```java
@Value("#{T(java.lang.Math).PI}")
private double pi;
```

Equivalent Java:

```java
Math.PI
```

Result:

```text
3.1415926535...
```

---

Calling static methods:

```java
@Value("#{T(java.lang.Math).max(10,20)}")
private int max;
```

Equivalent:

```java
Math.max(10,20)
```

Result:

```text
20
```

---

# 9. Reference collections

SpEL supports lists, maps, arrays, and collection operations.

## List

```java
@Value("#{{'Java','Spring','Docker'}}")
private List<String> tools;
```

Result:

```text
[
 Java,
 Spring,
 Docker
]
```

---

## Access an element

```java
@Value("#{{'Java','Spring'}[0]}")
private String first;
```

Result:

```text
Java
```

---

## Map

```java
@Value("#{{'name':'Mike','age':30}}")
private Map<String,Object> user;
```

Result:

```text
{
 name=Mike,
 age=30
}
```

---

# 10. Reference properties from configuration (`${}`)

This is an important exam point.

SpEL can combine with Spring property placeholders.

Example:

`application.properties`

```properties
app.timeout=5000
```

Java:

```java
@Value("#{${app.timeout} * 2}")
private int timeout;
```

Evaluation happens in two steps:

### Step 1: Property resolution

```text
${app.timeout}
        ↓
5000
```

### Step 2: SpEL evaluation

```text
#{5000 * 2}
        ↓
10000
```

Result:

```text
timeout = 10000
```

Remember:

```text
${...} → read configuration property

#{...} → evaluate expression
```

---

# 11. Reference operators and expressions

SpEL can reference expressions.

## Arithmetic

```java
@Value("#{10 + 5}")
```

Result:

```text
15
```

---

## Comparison

```java
@Value("#{10 > 5}")
```

Result:

```text
true
```

---

## Conditional operator

```java
@Value("#{10 > 5 ? 'big' : 'small'}")
```

Result:

```text
big
```

---

# 12. Reference the current object (`this`)

Inside certain SpEL contexts, you can reference the current object.

Example concept:

```text
this.property
```

This is more common when working with advanced Spring features rather than simple `@Value`.

---

# 13. Reference nested properties

SpEL supports chaining.

Example:

```java
#{user.address.city}
```

Equivalent:

```java
user.getAddress().getCity()
```

Example object graph:

```text
User
 |
 +-- Address
        |
        +-- City
```

SpEL:

```text
user.address.city
```

returns:

```text
New York
```

# 14. Summary of things SpEL can reference

| Reference type           | Example                               |
| ------------------------ | ------------------------------------- |
| Literal values           | `#{100}`                              |
| Strings                  | `#{'hello'}`                          |
| Arithmetic expressions   | `#{2+3}`                              |
| Bean properties          | `#{user.name}`                        |
| Spring Beans             | `#{myBean}`                           |
| Bean methods             | `#{myBean.calculate()}`               |
| System properties        | `#{systemProperties['java.version']}` |
| Environment variables    | `#{systemEnvironment['PATH']}`        |
| Variables                | `#variableName`                       |
| Java types               | `#{T(java.lang.Math).PI}`             |
| Static methods           | `#{T(Math).max(1,2)}`                 |
| Lists                    | `#{ {'A','B'} }`                      |
| Maps                     | `#{ {'key':'value'} }`                |
| Configuration properties | `${app.name}`                         |

# SpEL and Spring Container relationship

A useful mental model:

```
                Spring ApplicationContext
                         |
                         |
                    SpEL Engine
                         |
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
      Beans          Properties       Runtime objects
        ↓                ↓                ↓
   bean.method()   ${property}     systemEnvironment
```

SpEL acts as a bridge between:

* Spring Beans
* Java objects
* Configuration
* Runtime information

# Exam-ready answer

> **SpEL (Spring Expression Language) can reference literal values, properties of objects, Spring Beans, methods, system properties, environment variables, variables, Java types, collections, and values from Spring configuration properties. It is commonly used with `@Value` and uses the `#{...}` syntax to evaluate expressions at runtime.**

### Short version to memorize:

```
SpEL can reference:

✓ literals
✓ Bean properties
✓ Spring Beans
✓ Bean methods
✓ system properties
✓ environment variables
✓ variables
✓ Java types (T(...))
✓ collections
✓ configuration values (${...})

Syntax:
    #{expression}
```

The most important interview distinction:

```
${...}  → Property placeholder (find a value)
#{...}  → SpEL expression (calculate/evaluate a value)
```
