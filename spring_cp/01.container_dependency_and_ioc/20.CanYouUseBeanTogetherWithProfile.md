# Can you use `@Bean` together with `@Profile`?

Yes. **`@Bean` and `@Profile` can be used together**, and this is a very common pattern in Spring applications.

The key idea:

> **`@Bean` defines a Bean, while `@Profile` controls whether that Bean should be created depending on the active Spring profile.**

In short:

```text
@Bean
        ↓
Define a Bean

@Profile
        ↓
Decide when the Bean exists
```

Together:

```java
@Bean
@Profile("dev")
public DataSource dataSource() {
    return new H2DataSource();
}
```

means:

> "Create this DataSource Bean only when the `dev` profile is active."

---

# 1. Basic example

Suppose we have different databases.

## Development database

```java
@Configuration
public class DatabaseConfig {


    @Bean
    @Profile("dev")
    public DataSource devDataSource() {

        return new H2DataSource();
    }

}
```

This Bean exists only when:

```properties
spring.profiles.active=dev
```

---

## Production database

```java
@Configuration
public class DatabaseConfig {


    @Bean
    @Profile("prod")
    public DataSource prodDataSource() {

        return new MySQLDataSource();
    }

}
```

This Bean exists only when:

```properties
spring.profiles.active=prod
```

---

# 2. What happens during application startup?

Assume:

```properties
spring.profiles.active=dev
```

Spring startup:

```text
ApplicationContext startup

        |
        ↓

Read active profiles

        |
        ↓

Find @Bean methods

        |
        ↓

Check @Profile conditions

        |
        ↓

Is "dev" active?

        |
        +---- Yes
        |       |
        |       ↓
        |   Create Bean
        |
        +---- No
                |
                ↓
            Ignore Bean
```

# 3. Example with multiple Beans

A common real-world case:

```java
@Configuration
public class PaymentConfig {


    @Bean
    @Profile("dev")
    public PaymentService mockPaymentService() {

        return new MockPaymentService();
    }


    @Bean
    @Profile("prod")
    public PaymentService realPaymentService() {

        return new StripePaymentService();
    }

}
```

Development:

```text
Active profile:
dev


ApplicationContext:

PaymentService
       |
       ↓
MockPaymentService
```

Production:

```text
Active profile:
prod


ApplicationContext:

PaymentService
       |
       ↓
StripePaymentService
```

Your business code does not change:

```java
@Service
public class OrderService {


    private final PaymentService paymentService;


    public OrderService(
            PaymentService paymentService) {

        this.paymentService = paymentService;
    }

}
```

Spring injects the correct implementation.

# 4. `@Profile` on `@Configuration` vs `@Bean`

You can put `@Profile` in two places.

---

## Option 1: Put it on the `@Bean`

Example:

```java
@Configuration
public class AppConfig {


    @Bean
    @Profile("dev")
    public EmailService emailService() {

        return new FakeEmailService();
    }

}
```

Only this Bean is conditional.

Other Beans in the configuration still exist.

---

## Option 2: Put it on the configuration class

Example:

```java
@Configuration
@Profile("dev")
public class DevConfig {


    @Bean
    public EmailService emailService() {

        return new FakeEmailService();
    }

}
```

Now:

```text
dev profile active

        ↓

DevConfig loaded

        ↓

EmailService created
```

If:

```text
prod profile active
```

then:

```text
DevConfig ignored

        ↓

No Beans inside it created
```

---

# 5. Comparison

| Location                  | Effect                                         |
| ------------------------- | ---------------------------------------------- |
| `@Bean @Profile`          | Controls one Bean                              |
| `@Configuration @Profile` | Controls all Beans in that configuration class |

Example:

```java
@Configuration
@Profile("prod")
public class ProductionConfig {

    @Bean
    public A a(){}

    @Bean
    public B b(){}

}
```

means:

```text
prod active:

A created
B created


prod inactive:

A ignored
B ignored
```

# 6. Using `@Bean`, `@Profile`, and `@Qualifier` together

Sometimes you have multiple implementations.

Example:

```java
@Configuration
public class PaymentConfig {


    @Bean
    @Profile("dev")
    @Qualifier("payment")
    public PaymentService mockPayment(){

        return new MockPaymentService();
    }


    @Bean
    @Profile("prod")
    @Qualifier("payment")
    public PaymentService realPayment(){

        return new StripePaymentService();
    }

}
```

The application code:

```java
@Service
public class OrderService {


    public OrderService(
        @Qualifier("payment")
        PaymentService service) {

    }

}
```

Flow:

```text
Profile decides:

Does the Bean exist?


        ↓


Qualifier decides:

Which Bean should be injected?
```

# 9. Important interview point

Question:

> Can you use `@Bean` together with `@Profile`?

Answer:

> **Yes. `@Profile` can be applied to methods annotated with `@Bean`. The Bean will only be registered in the Spring ApplicationContext when the specified profile is active. This is commonly used to provide different implementations or configurations for different environments such as development, testing, and production.**

---

# 10. Short version to memorize

```text
@Bean
=
Create a Spring Bean


@Profile
=
Conditionally create that Bean


Together:

@Bean
@Profile("dev")
public Service service()
```

means:

```text
If dev profile is active:
        create Service Bean

Otherwise:
        do not create it
```

A good mental model:

> **`@Bean` answers "what object should Spring create?"
> `@Profile` answers "when should Spring create it?"**
