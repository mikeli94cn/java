# What is Spring Expression Language (SpEL)?

**SpEL (Spring Expression Language)** is an expression language provided by the Spring Framework that allows you to **evaluate expressions dynamically at runtime**.

In simple terms:

> **SpEL lets you write expressions inside Spring configuration/annotations to calculate values, access objects, call methods, and make conditional decisions.**

The most common place you've just seen it is with `@Value`.

```java
@Value("#{2 + 3}")
private int number;
```

Spring evaluates:

```text
2 + 3
 ↓
 5
```

and injects `5` into `number`.

---

# 1. Why does Spring need SpEL?

Normally Java code performs calculations and method calls:

```java
int result = 10 + 20;
```

But Spring configuration often needs to dynamically express things like:

```text
calculate a value
read a system property
access a Bean
call a method
choose between values
check a condition
access a collection
```

SpEL provides a unified syntax for doing these things inside Spring.

Conceptually:

```text
Java application
       │
       ↓
Spring Framework
       │
       ↓
      SpEL
       │
       ├── calculate
       ├── access properties
       ├── call methods
       ├── access Beans
       ├── conditions
       └── collections
```

---

# 2. Basic SpEL syntax

The most recognizable SpEL syntax is:

```java
#{expression}
```

For example:

```java
@Value("#{2 + 3}")
private int result;
```

The `#{...}` tells Spring:

> **Evaluate this as a SpEL expression.**

Result:

```text
result = 5
```

---

# 3. SpEL can perform arithmetic

For example:

```java
@Value("#{10 + 20}")
private int a;

@Value("#{10 * 5}")
private int b;

@Value("#{100 / 4}")
private int c;
```

Results:

```text
a = 30
b = 50
c = 25
```

You can use:

```text
+   addition
-   subtraction
*   multiplication
/   division
%   remainder
```

---

# 4. SpEL can compare values

For example:

```java
@Value("#{10 > 5}")
private boolean result;
```

Result:

```text
true
```

You can perform comparisons such as:

```java
@Value("#{10 == 10}")
private boolean a;

@Value("#{10 > 5}")
private boolean b;

@Value("#{10 < 5}")
private boolean c;
```

Conceptually:

```text
10 == 10 → true
10 > 5   → true
10 < 5   → false
```

---

# 5. SpEL can access Bean properties

This is one of its more interesting features.

Suppose Spring has:

```java
@Component("user")
public class User {

    private String name = "Mike";

    public String getName() {
        return name;
    }
}
```

Another Bean can use:

```java
@Value("#{user.name}")
private String userName;
```

Spring evaluates:

```text
user.name
   ↓
User Bean
   ↓
getName()
   ↓
"Mike"
```

So SpEL can interact with the **Spring IoC container**.

---

# 6. SpEL can call methods

For example:

```java
@Value("#{user.getName()}")
private String name;
```

It can also call methods on objects.

For example:

```java
@Value("#{'hello'.toUpperCase()}")
private String message;
```

Result:

```text
HELLO
```

So SpEL can do things like:

```text
object
  ↓
property
  ↓
method
  ↓
result
```

---

# 7. SpEL can access system properties

For example:

```java
@Value("#{systemProperties['user.home']}")
private String home;
```

This accesses a JVM system property.

Another example:

```java
@Value("#{systemProperties['java.version']}")
private String javaVersion;
```

So SpEL can interact with the runtime environment.

---

# 8. SpEL and `@Value`: an important distinction

You just learned about:

```java
@Value("${app.port}")
```

and now:

```java
@Value("#{2 + 3}")
```

These look similar but mean different things.

### `${...}` = property placeholder

```java
@Value("${app.port}")
```

means:

> Find the configuration property named `app.port`.

For example:

```properties
app.port=8080
```

Result:

```text
8080
```

### `#{...}` = SpEL

```java
@Value("#{2 + 3}")
```

means:

> Evaluate this SpEL expression.

Result:

```text
5
```

This distinction is **very important for Spring exams/interviews**.

```text
${...}
   ↓
Property placeholder
   ↓
Read configuration

#{...}
   ↓
SpEL expression
   ↓
Evaluate expression
```

---

# 9. They can also be combined

This is particularly useful.

Suppose:

```properties
app.price=100
```

You can write:

```java
@Value("#{${app.price} * 2}")
private int doublePrice;
```

Conceptually:

```text
${app.price}
      ↓
     100
      ↓
#{100 * 2}
      ↓
     200
```

So:

```text
${...} → retrieve configuration
#{...} → evaluate expression
```

They can work together.

---

# 10. SpEL can use the ternary operator

For example:

```java
@Value("#{10 > 5 ? 'yes' : 'no'}")
private String answer;
```

Result:

```text
yes
```

Conceptually:

```text
condition
    │
    ↓
10 > 5 ?
 ┌──┴──┐
yes    no
 ↓      ↓
"yes"  "no"
```

This allows configuration-dependent values.

---

# 11. SpEL can access collections

SpEL supports collection operations.

For example:

```java
@Value("#{ {'Java', 'Spring', 'Docker'} }")
private List<String> technologies;
```

Conceptually:

```text
["Java", "Spring", "Docker"]
```

You can also access elements.

For example:

```java
@Value("#{{'Java', 'Spring', 'Docker'}[0]}")
private String first;
```

Result:

```text
Java
```

---

# 12. SpEL supports selection and filtering

SpEL has more advanced collection features.

For example, conceptually:

```text
collection
    ↓
selection
    ↓
elements satisfying condition
```

This can be useful when working with collections of objects.

You probably don't need to memorize the advanced syntax for a beginner Spring exam, but it's useful to know that SpEL is much more than arithmetic.

---

# 13. SpEL can reference types

SpEL uses `T(...)` to refer to a Java type.

For example:

```java
@Value("#{T(java.lang.Math).PI}")
private double pi;
```

This accesses:

```java
Math.PI
```

Another example:

```java
@Value("#{T(java.lang.Math).max(10, 20)}")
private int maximum;
```

Result:

```text
20
```

The pattern is:

```text
T(Type)
   ↓
access static fields/methods
```

For example:

```java
T(java.lang.Math).max(10, 20)
```

---

# 14. Where is SpEL used?

SpEL appears in several parts of the Spring ecosystem.

### `@Value`

Most common beginner example:

```java
@Value("#{2 + 3}")
private int value;
```

### `@Conditional`-related mechanisms

Spring supports conditional configuration, although modern Spring Boot applications often use dedicated condition annotations rather than writing SpEL directly.

### Security

Spring Security has historically used expressions for authorization rules, for example:

```text
hasRole(...)
hasAuthority(...)
```

### Spring Data

Expressions can also appear in some Spring Data features.

So SpEL is a **general Spring infrastructure feature**, not merely an `@Value` feature.

---

# 15. SpEL vs Java

An important conceptual point:

**SpEL is not a replacement for Java.**

You don't normally write your application business logic in SpEL.

Bad idea:

```text
huge complicated business algorithm
        ↓
       SpEL
```

Instead:

```text
Business logic → Java
Configuration / dynamic Spring expressions → SpEL
```

For example, this is reasonable:

```java
@Value("#{${app.max-users} * 2}")
private int capacity;
```

But putting a large business algorithm into an annotation would be difficult to maintain.

---

# 16. SpEL vs `${...}`

This is probably the most important thing to remember from this topic.

| Syntax   | Meaning              | Example          |
| -------- | -------------------- | ---------------- |
| `${...}` | Property placeholder | `${server.port}` |
| `#{...}` | SpEL expression      | `#{2 + 3}`       |

Think:

```text
${...}
   ↓
"Where is my configuration value?"

#{...}
   ↓
"Evaluate this expression."
```

You've now built a nice chain:

```text
Spring IoC
    ↓

    ↓
Beans
    ↓
Dependency Injection
    ↓
Configuration
    ↓

    ↓
Environment
    ↓
```

```text
                 @Value
                   │
          ┌────────┴────────┐
          ↓                 ↓
       ${...}             #{...}
          │                 │
          ↓                 ↓
  Property lookup       Expression
          │              evaluation
          └────────┬────────┘
                   ↓
             injected value
```

## Exam-ready answer

> **Spring Expression Language (SpEL) is an expression language provided by the Spring Framework that supports querying and manipulating objects at runtime. It can perform calculations, comparisons, access object properties and methods, reference Spring Beans, access collections and system properties, and evaluate conditional expressions. SpEL expressions are commonly written using `#{...}`, such as `@Value("#{2 + 3}")`.**

### Short version to memorize

```text
SpEL = Spring Expression Language

Purpose:
    evaluate dynamic expressions at runtime

Syntax:
    #{...}

Can:
    ✓ calculate
    ✓ compare
    ✓ access properties
    ✓ call methods
    ✓ access Beans
    ✓ access collections
    ✓ reference Java types

Most common:
    @Value("#{...}")

Remember:
    ${...} = property placeholder
    #{...} = SpEL expression
```

The **`${...}` vs `#{...}` distinction** is especially worth remembering because it connects your previous topic—**injecting scalar/configuration values**—directly to SpEL.
