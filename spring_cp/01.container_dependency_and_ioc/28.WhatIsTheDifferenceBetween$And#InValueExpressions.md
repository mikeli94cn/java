# What is the difference between `$` and `#` in `@Value` expressions?

This is a very common Spring interview/exam question.

The short answer:

> **`${...}` is used for property placeholders (reading configuration values), while `#{...}` is used for SpEL (Spring Expression Language) expressions (evaluating expressions).**

They look similar but serve completely different purposes.

---

# 1. `${...}` = Property Placeholder

`${}` tells Spring:

> "Find this value from the Spring Environment."

Example:

`application.properties`

```properties
app.name=Order System
app.port=8080
```

Java:

```java
@Component
public class AppConfig {

    @Value("${app.name}")
    private String name;

    @Value("${app.port}")
    private int port;
}
```

Spring performs:

```text
${app.name}
       ↓
Environment lookup
       ↓
"Order System"
       ↓
inject into name
```

Result:

```java
name = "Order System"
port = 8080
```

---

# 2. `#{...}` = SpEL Expression

`#{}` tells Spring:

> "Evaluate this as a Spring Expression Language expression."

Example:

```java
@Component
public class Calculator {

    @Value("#{10 + 20}")
    private int result;
}
```

Spring evaluates:

```text
#{10 + 20}
       ↓
SpEL engine
       ↓
30
```

Result:

```java
result = 30;
```

---

# 3. The simplest comparison

| Syntax   | Meaning               | Example       | Result                   |
| -------- | --------------------- | ------------- | ------------------------ |
| `${...}` | Property lookup       | `${app.name}` | Value from configuration |
| `#{...}` | Expression evaluation | `#{2 + 3}`    | Calculated result        |

Remember:

```text
${}
 ↓
"Where is this configuration value?"

#{}
 ↓
"What is the result of this expression?"
```

---

# 4. `${}` example in detail

Suppose:

```properties
server.port=8080
```

Code:

```java
@Value("${server.port}")
private int port;
```

Spring does:

```
1. Read expression:
       ${server.port}

2. Search Environment:
       server.port = 8080

3. Convert String to int

4. Inject:
       port = 8080
```

The source could be:

```
application.properties
        +
environment variables
        +
command line arguments
        +
system properties
```

because they are all part of Spring's `Environment`.

---

# 5. `#{}` example in detail

Example:

```java
@Value("#{5 * 10}")
private int value;
```

Spring does:

```
1. Read expression:
       #{5 * 10}

2. Send to SpEL parser

3. Evaluate:

       5 * 10

4. Inject:

       value = 50
```

No property file is involved.

---

# 6. They can be combined

This is where it becomes powerful.

Suppose:

```properties
app.maxUsers=100
```

You want double the value.

You can write:

```java
@Value("#{${app.maxUsers} * 2}")
private int maxUsers;
```

Spring processes it in two stages:

## Step 1: Resolve `${}`

```
${app.maxUsers}
        ↓
       100
```

Now the expression becomes:

```
#{100 * 2}
```

## Step 2: Evaluate `#{}`

```
100 * 2
   ↓
200
```

Final result:

```java
maxUsers = 200;
```

So:

```text
${...}
   ↓
property resolution

#{...}
   ↓
expression evaluation
```

---

# 7. Default values with `${}`

A very common Spring Boot pattern:

```java
@Value("${app.timeout:5000}")
private int timeout;
```

Meaning:

```
Does app.timeout exist?
        |
    +---+---+
    |       |
   yes      no
    |        |
 use it    use 5000
```

Example:

No configuration:

```properties
(no app.timeout)
```

Result:

```java
timeout = 5000;
```

---

# 8. Referencing Beans with `#{}`

SpEL can access Spring Beans.

Example:

```java
@Component("calculator")
public class Calculator {

    public int add(int a, int b) {
        return a + b;
    }
}
```

Use:

```java
@Value("#{calculator.add(10,20)}")
private int result;
```

Spring does:

```
calculator Bean
       ↓
add(10,20)
       ↓
30
```

This is impossible with `${}`.

---

# 9. Accessing system properties with `#{}`

Example:

```java
@Value("#{systemProperties['java.version']}")
private String version;
```

Equivalent to:

```java
System.getProperty("java.version");
```

Example result:

```
21.0.1
```

---

# 10. Common mistakes

## Mistake 1: Using `#{}` for properties

Wrong:

```java
@Value("#{app.name}")
private String name;
```

Spring thinks:

```
app.name
```

is a SpEL expression.

It tries to find an object/property named `app`.

Usually this fails.

Correct:

```java
@Value("${app.name}")
private String name;
```

---

## Mistake 2: Using `${}` for calculations

Wrong:

```java
@Value("${2 + 3}")
private int result;
```

Spring thinks:

```
property named "2 + 3"
```

exists.

Usually it does not.

Correct:

```java
@Value("#{2 + 3}")
private int result;
```

---

# 11. Relationship with Environment

Remember the previous topic:

```
Property Sources
        |
        ↓
Environment
        |
        ↓
${property.name}
        |
        ↓
@Value injection
```

while:

```
Java objects
       |
       ↓
SpEL engine
       |
       ↓
#{expression}
       |
       ↓
@Value injection
```

---

# 12. Relationship with `@ConfigurationProperties`

Modern Spring Boot applications often prefer:

```java
@ConfigurationProperties
```

for large configuration groups.

Example:

```properties
database.url=localhost
database.username=root
database.password=123456
```

Instead of:

```java
@Value("${database.url}")
@Value("${database.username}")
@Value("${database.password}")
```

you create:

```java
@ConfigurationProperties(prefix="database")
public class DatabaseProperties {

    private String url;
    private String username;
    private String password;
}
```

But the distinction remains:

```
${}
 → configuration binding

#{}
 → expression evaluation
```

---

# 13. Exam-ready answer

> **In a Spring `@Value` expression, `${}` is a property placeholder that resolves values from Spring's Environment and PropertySources, such as application.properties, environment variables, or system properties. `#{}` is a SpEL expression that evaluates expressions at runtime, such as calculations, method calls, Bean references, and conditional expressions. They can also be combined, where `${}` resolves a property first and `#{}` evaluates the resulting expression.**

---

## Quick memory table

|                   | `${}`                  | `#{}`                  |
| ----------------- | ---------------------- | ---------------------- |
| Name              | Property placeholder   | SpEL expression        |
| Purpose           | Retrieve configuration | Evaluate expressions   |
| Source            | Environment            | SpEL engine            |
| Example           | `${server.port}`       | `#{2 + 3}`             |
| Reads properties  | ✅                      | Can combine with `${}` |
| Does calculations | ❌                      | ✅                      |
| Calls methods     | ❌                      | ✅                      |
| References Beans  | ❌                      | ✅                      |

The key sentence for the exam:

> **Dollar means "look up a value"; hash means "evaluate an expression."**
