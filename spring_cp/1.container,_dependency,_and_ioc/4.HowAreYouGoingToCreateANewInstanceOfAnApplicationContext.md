# How do you create a new instance of an `ApplicationContext`?

This exam question is really asking:

> **How can we create a Spring IoC container?**

The answer depends on **how your Spring application is configured**.

For a beginner, there are three important approaches to know:

```text
Create ApplicationContext
        |
        +── Java configuration
        |
        +── XML configuration
        |
        +── Spring Boot
```

---

# 1. Java configuration — `AnnotationConfigApplicationContext`

This is the most important traditional approach to understand.

First, create a configuration class:

```java
@Configuration
@ComponentScan("com.example")
public class AppConfig {
}
```

Then create the context:

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(
        AppConfig.class
    );
```

The important part is:

```java
new AnnotationConfigApplicationContext(AppConfig.class)
```

Conceptually:

```text
AppConfig
   |
   ↓
AnnotationConfigApplicationContext
   |
   ↓
ApplicationContext
   |
   ↓
Spring Beans
```

---

# 2. A complete example

Suppose we have:

```java
@Component
public class UserService {

    public void hello() {
        System.out.println("Hello");
    }
}
```

Configuration:

```java
@Configuration
@ComponentScan("com.example")
public class AppConfig {
}
```

Create the container:

```java
public class Main {

    public static void main(String[] args) {

        ApplicationContext context =
            new AnnotationConfigApplicationContext(
                AppConfig.class
            );

        UserService service =
            context.getBean(UserService.class);

        service.hello();
    }
}
```

The flow is:

```text
AppConfig
    |
    ↓
AnnotationConfigApplicationContext
    |
    ↓
Component Scan
    |
    ↓
Find @Component
    |
    ↓
Create UserService Bean
    |
    ↓
Store/manage Bean
    |
    ↓
getBean()
```

---

# 3. XML configuration — `ClassPathXmlApplicationContext`

Older Spring applications commonly use XML configuration.

For example:

```xml
<beans>

    <bean id="userService"
          class="com.example.UserService"/>

</beans>
```

Then:

```java
ApplicationContext context =
    new ClassPathXmlApplicationContext(
        "applicationContext.xml"
    );
```

Here:

```text
applicationContext.xml
          |
          ↓
ClassPathXmlApplicationContext
          |
          ↓
ApplicationContext
          |
          ↓
Spring Beans
```

You can then retrieve the bean:

```java
UserService service =
    context.getBean(UserService.class);
```

---

# 4. `AnnotationConfigApplicationContext` vs `ClassPathXmlApplicationContext`

You should know this distinction for an exam.

| Class                                | Configuration                 |
| ------------------------------------ | ----------------------------- |
| `AnnotationConfigApplicationContext` | Java/annotation configuration |
| `ClassPathXmlApplicationContext`     | XML configuration             |

Examples:

```java
new AnnotationConfigApplicationContext(AppConfig.class);
```

versus:

```java
new ClassPathXmlApplicationContext(
    "applicationContext.xml"
);
```

Both produce an `ApplicationContext`.

```text
                ApplicationContext
                       ↑
             implements interface
                       |
          +------------+------------+
          |                         |
          ↓                         ↓
AnnotationConfig...        ClassPathXml...
          |                         |
    Java/annotations              XML
```

---

# 5. Spring Boot — usually you don't create it manually

In modern Spring Boot applications, you normally write:

```java
@SpringBootApplication
public class Application {

    public static void main(String[] args) {

        SpringApplication.run(
            Application.class,
            args
        );
    }
}
```

You don't normally write:

```java
new AnnotationConfigApplicationContext(...)
```

yourself.

Instead:

```text
SpringApplication.run()
        |
        ↓
Spring Boot creates/configures
ApplicationContext
        |
        ↓
Component scanning
        |
        ↓
Auto-configuration
        |
        ↓
Create Beans
        |
        ↓
Inject dependencies
        |
        ↓
Start application
```

You can still obtain the context if you need it:

```java
ConfigurableApplicationContext context =
    SpringApplication.run(
        Application.class,
        args
    );
```

Notice that the return type is:

```java
ConfigurableApplicationContext
```

which is a specialized form of `ApplicationContext`.

---

# 6. Why does Spring Boot make this easier?

Traditional Spring:

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(
        AppConfig.class
    );
```

You have to explicitly create the container.

Spring Boot:

```java
SpringApplication.run(Application.class, args);
```

Spring Boot handles:

* creating the context
* configuration
* component scanning
* auto-configuration
* starting the embedded server
* creating and wiring Beans

So for modern Spring development:

> **You normally let Spring Boot create the `ApplicationContext` for you.**

Suppose:

```java

```

```text
main()
  |
  ↓

  |
  ↓
Create ApplicationContext
  |
  ↓
Read configuration
  |
  ↓
Component scanning
  |
  ↓
Discover Beans
  |
  ↓
Create Beans
  |
  ↓
Resolve dependencies
  |
  ↓
Dependency Injection
  |
  ↓
Initialize Beans
  |
  ↓
Application Ready
```

For example:

```text
UserController
      |
      ↓
UserService
      |
      ↓
UserRepository
```

Spring creates and connects them.

# 8. Important exam distinction

The question says:

> **"How are you going to create a new instance of an ApplicationContext?"**

Be careful: `ApplicationContext` is an **interface**, so you cannot do:

```java
new ApplicationContext();  // ❌
```

You need an implementation:

```java
new AnnotationConfigApplicationContext(...);
```

or:

```java
new ClassPathXmlApplicationContext(...);
```

This is exactly the same Java principle you already know from interfaces:

```java
List<String> list =
    new ArrayList<>();
```

You cannot:

```java
new List<>();  // ❌
```

Likewise:

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(...);
```

The variable uses the interface type, while the actual object is a concrete implementation.

---

# 9. Exam-ready answer

If this appears as a Spring exam question:

> **How are you going to create a new instance of an `ApplicationContext`?**

A good answer is:

> `ApplicationContext` is an interface, so it cannot be instantiated directly. We create an instance of one of its implementations. For Java-based configuration, we can use `AnnotationConfigApplicationContext`, for example:
>
> ```java
> ApplicationContext context =
>     new AnnotationConfigApplicationContext(AppConfig.class);
> ```
>
> For XML configuration, we can use:
>
> ```java
> ApplicationContext context =
>     new ClassPathXmlApplicationContext(
>         "applicationContext.xml");
> ```
>
> In Spring Boot, we normally let `SpringApplication.run()` create and configure the `ApplicationContext` automatically.
