# What is a proxy object and what are the two different types of proxies Spring can create?

This topic is one of the most important Spring framework internals topics because it explains how Spring implements features like:

* `@Transactional`
* `@Aspect`
* security (`@PreAuthorize`)
* caching (`@Cacheable`)
* logging
* monitoring

The key idea:

> **A proxy object is an object created by Spring that wraps the original Bean and intercepts method calls to add extra behavior before delegating to the real object.**

In simple words:

```text
Your code
    |
    ↓
Proxy object
    |
    ↓
Real Bean
```

The proxy acts as a "middle layer".

---

# 1. Why does Spring need proxy objects?

Consider a normal Java object:

```java
public class PaymentService {

    public void pay() {
        System.out.println("Processing payment");
    }
}
```

Calling:

```java
paymentService.pay();
```

directly executes:

```text
pay()
 |
 ↓
Business logic
```

But Spring wants to add extra behavior.

For example:

```java
@Transactional
public void pay() {

}
```

Spring needs to do:

```text
Start transaction

      ↓

Execute pay()

      ↓

Commit transaction
```

without changing your business code.

How?

By creating a proxy:

```text
Caller
  |
  ↓
PaymentService Proxy
  |
  |-- start transaction
  |
  ↓
Real PaymentService
  |
  |-- pay()
  |
  ↓
Proxy
  |
  |-- commit transaction
```

The proxy intercepts the method call.

---

# 2. Proxy pattern concept

The proxy pattern is a classic object-oriented design pattern.

The structure:

```text
Client

  |
  ↓

Proxy Object

  |
  ↓

Real Object
```

The client thinks it is calling the real object:

```java
paymentService.pay();
```

but actually:

```text
paymentService
        |
        ↓
PaymentServiceProxy
```

The proxy controls access.

---

# 3. Spring proxy example

Suppose:

```java
@Service
public class OrderService {


    @Transactional
    public void createOrder() {

        System.out.println("Create order");
    }
}
```

You expect:

```java
OrderService service =
        context.getBean(OrderService.class);

service.createOrder();
```

But Spring actually returns:

```text
OrderService Proxy
```

not:

```text
OrderService
```

The object graph:

```text
ApplicationContext

      |
      ↓

OrderService Proxy

      |
      ↓

OrderService
```

---

# 4. What does the proxy do?

When you call:

```java
service.createOrder();
```

the proxy performs:

```text
1. Receive method call

        ↓

2. Check interceptors

        ↓

3. Start transaction

        ↓

4. Call real method

        ↓

5. Commit transaction
```

The original class remains clean:

```java
public void createOrder() {

    // only business logic

}
```

---

# 5. The two types of Spring proxies

Spring can create two types of proxies:

1. **JDK Dynamic Proxy**
2. **CGLIB Proxy**

---

# 6. JDK Dynamic Proxy

JDK Dynamic Proxy is based on Java's built-in reflection mechanism.

It requires:

> The target class must implement an interface.

Example:

Interface:

```java
public interface PaymentService {

    void pay();

}
```

Implementation:

```java
@Service
public class PaymentServiceImpl
        implements PaymentService {


    public void pay() {
        System.out.println("Pay");
    }

}
```

Spring creates:

```text
PaymentService Proxy
        |
        ↓
PaymentServiceImpl
```

The proxy implements the same interface:

```java
PaymentService proxy;
```

The caller sees:

```java
PaymentService
```

not:

```java
PaymentServiceImpl
```

---

## Internally

Conceptually:

```java
class JdkProxy
        implements PaymentService {


    private PaymentServiceImpl target;


    public void pay() {

        before();

        target.pay();

        after();
    }
}
```

---

# 7. CGLIB Proxy

CGLIB creates a subclass of the target class.

It does not require an interface.

Example:

```java
@Service
public class PaymentService {


    public void pay() {

    }

}
```

Spring creates:

```text
PaymentService$$SpringCGLIBProxy
             |
             ↓
     PaymentService
```

Conceptually:

```java
class PaymentServiceProxy
        extends PaymentService {


    @Override
    public void pay() {

        before();

        super.pay();

        after();
    }
}
```

---

# 8. Comparison between JDK Proxy and CGLIB

|                          | JDK Dynamic Proxy    | CGLIB Proxy       |
| ------------------------ | -------------------- | ----------------- |
| Based on                 | Java reflection      | Class inheritance |
| Requires interface?      | Yes                  | No                |
| Proxy type               | Implements interface | Extends class     |
| Can proxy classes?       | No                   | Yes               |
| Can proxy final methods? | No                   | No                |
| Used by Spring           | Yes                  | Yes               |

---

# 9. Which proxy does Spring use?

Modern Spring behavior:

## If the Bean implements an interface:

Spring normally uses:

```text
JDK Dynamic Proxy
```

Example:

```java
public interface UserService {

}


@Service
public class UserServiceImpl
        implements UserService {

}
```

Proxy:

```text
UserService Proxy
```

---

## If the Bean does not implement an interface:

Spring uses:

```text
CGLIB Proxy
```

Example:

```java
@Service
public class UserService {

}
```

Proxy:

```text
UserService$$SpringCGLIBProxy
```

---

# 10. Forcing CGLIB proxy

You can configure Spring Boot:

```properties
spring.aop.proxy-target-class=true
```

This tells Spring:

> Always use CGLIB proxies.

Example:

```text
Interface exists?

       ↓

Ignore JDK proxy

       ↓

Use CGLIB
```

# 11. Relationship with `BeanPostProcessor`

This connects to your previous topic.

Remember:

```text
BeanFactoryPostProcessor
        |
        ↓
Modify BeanDefinition


BeanPostProcessor
        |
        ↓
Modify Bean instance
```

Proxy creation happens through `BeanPostProcessor`.

The lifecycle:

```text
Create Bean

     ↓

Initialize Bean

     ↓

BeanPostProcessor

     ↓

Create Proxy

     ↓

Return Proxy to ApplicationContext
```

So the container stores:

```text
Proxy
```

instead of:

```text
Original Bean
```

# 12. Example with `@Transactional`

Code:

```java
@Service
public class BankService {


    @Transactional
    public void transfer() {

        withdraw();

        deposit();
    }
}
```

Spring creates:

```text
BankService Proxy

       |
       ↓

BankService
```

Call:

```java
service.transfer();
```

Actually:

```text
Proxy.transfer()

      |
      ↓

Begin transaction

      |
      ↓

BankService.transfer()

      |
      ↓

Commit transaction
```

# 13. Important proxy limitation: self-invocation

A common interview question.

Example:

```java
@Service
public class UserService {


    @Transactional
    public void save() {

    }


    public void process() {

        save();
    }
}
```

Call:

```java
userService.process();
```

Inside:

```java
save();
```

does NOT go through the proxy.

Why?

Because:

```text
process()
   |
   ↓
this.save()
```

calls the original object directly.

Not:

```text
Proxy
 |
 ↓
save()
```

Therefore:

```text
@Transactional
may not work
```

# 14. Proxy and dependency injection

When you inject:

```java
@Autowired
private UserService service;
```

you may think:

```text
UserService object
```

but actually:

```text
UserService Proxy
```

Example:

```text
@Autowired

       ↓

ApplicationContext

       ↓

UserService Proxy

       ↓

Real UserService
```

This is why Spring can transparently add behavior.

---

# 15. Why use proxies instead of modifying classes?

Alternative:

```java
public void pay() {

    startTransaction();

    businessLogic();

    commit();

}
```

Problems:

* duplicated code
* business logic mixed with infrastructure
* difficult maintenance

Proxy approach:

```java
@Transactional
public void pay(){

    businessLogic();

}
```

Spring handles:

* transactions
* security
* logging
* caching

This is called:

> **separation of concerns**

---

# 16. Exam-ready answer

Question:

> **What is a proxy object and what are the two different types of proxies Spring can create?**

A strong answer:

> **A proxy object is an object created by Spring that wraps the original Bean and intercepts method calls to add additional behavior such as transactions, security, logging, or caching. The application usually interacts with the proxy instead of the real Bean. Spring creates two types of proxies: JDK Dynamic Proxies and CGLIB Proxies. JDK Dynamic Proxies are interface-based and create an object implementing the target interface. CGLIB proxies create a subclass of the target class and can proxy classes without interfaces.**
