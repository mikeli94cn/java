# What is `ApplicationContext` in Spring?

`ApplicationContext` is one of the **most important interfaces in Spring**.

The simplest definition is:

> **`ApplicationContext` is Spring's IoC container. It creates, configures, manages, and provides Spring Beans and their dependencies.**

If you're studying for a Spring exam, remember this relationship:

```text
ApplicationContext
        ↓
    IoC Container
        ↓
  manages Beans
        ↓
Dependency Injection
```

---

# 1. First: what problem does it solve?

In normal Java, you create objects yourself:

```java
UserRepository repository =
    new UserRepository();

UserService service =
    new UserService(repository);
```

You are responsible for:

* creating objects
* deciding which implementation to use
* connecting objects together
* managing their lifecycle

With Spring:

```text
             ApplicationContext
                    |
          creates and manages
                    |
          +---------+---------+
          |                   |
          ↓                   ↓
 UserRepository          UserService
                              |
                              ↓
                       UserRepository
```

Spring takes responsibility for creating and wiring these objects.

That is **Inversion of Control (IoC)**.

---

# 2. What exactly is `ApplicationContext`?

In Java:

```java
public interface ApplicationContext
        extends BeanFactory {
}
```

Conceptually:

```text
ApplicationContext
       |
       ↓
Spring IoC Container
       |
       +-- creates Beans
       +-- stores Beans
       +-- injects dependencies
       +-- manages lifecycle
       +-- provides configuration
       +-- publishes events
```

So when you hear:

> **Spring Container**

you will often encounter:

> **`ApplicationContext`**

as the main abstraction representing that container.

---

# 3. What is a Spring Bean?

Suppose we have:

```java
@Service
public class UserService {

}
```

Spring can create an instance of this class and manage it.

That object is called a **Spring Bean**.

```text
UserService class
       |
       | Spring creates
       ↓
UserService object
       |
       ↓
Spring Bean
```

The `ApplicationContext` manages that Bean.

---

# 4. A simple example

Suppose:

```java
@Component
public class HelloService {

    public void hello() {
        System.out.println("Hello Spring");
    }
}
```

We can create an `ApplicationContext`:

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(AppConfig.class);
```

Then ask Spring for the Bean:

```java
HelloService service =
    context.getBean(HelloService.class);
```

Now:

```java
service.hello();
```

Spring has effectively done:

```text
ApplicationContext
       |
       | getBean()
       ↓
HelloService Bean
```

---

# 5. How does Spring know about `HelloService`?

Usually through **component scanning**.

For example:

```java
@Configuration
@ComponentScan("com.example")
public class AppConfig {

}
```

Spring scans the package:

```text
com.example
    |
    +-- HelloService
    +-- UserService
    +-- UserRepository
```

It discovers classes such as:

```java
@Component
@Service
@Repository
@Controller
```

and registers them as Beans.

Conceptually:

```text
@ComponentScan
      |
      ↓
Find components
      |
      ↓
Register Beans
      |
      ↓
ApplicationContext
```

---

# 6. Dependency Injection through `ApplicationContext`

Consider:

```java
@Repository
public class UserRepository {

    public void save() {
        System.out.println("Saving user");
    }
}
```

And:

```java
@Service
public class UserService {

    private final UserRepository repository;

    public UserService(UserRepository repository) {
        this.repository = repository;
    }

}
```

Spring sees both classes.

It creates:

```text
UserRepository Bean
```

and:

```text
UserService Bean
```

Then it sees:

```java
UserService(UserRepository repository)
```

and injects the `UserRepository`.

Conceptually, Spring performs something like:

```java
UserRepository repository =
    new UserRepository();

UserService service =
    new UserService(repository);
```

The important point is that **your application doesn't have to manually perform this wiring**.

---

# 7. The object graph

This is one of the best ways to understand `ApplicationContext`.

Suppose your application contains:

```text
UserController
      |
      ↓
UserService
      |
      ↓
UserRepository
```

And:

```text
OrderController
      |
      ↓
OrderService
      |
      +------→ PaymentService
      |
      +------→ OrderRepository
```

The `ApplicationContext` manages this **object graph**.

```text
                 ApplicationContext
                        |
        +---------------+---------------+
        |                               |
        ↓                               ↓
 UserController                  OrderController
        |                               |
        ↓                               ↓
 UserService                    OrderService
        |                         /           \
        ↓                        ↓             ↓
 UserRepository          PaymentService   OrderRepository
```

This is a very useful mental model:

> **The Spring container manages the application's object graph.**

# 8. `ApplicationContext` is more than just an object factory

A beginner might think:

> "`ApplicationContext` just creates objects."

That's incomplete.

It provides several important services.

### ① Bean creation

```text
ApplicationContext
        ↓
   create Bean
```

### ② Dependency injection

```text
UserService
     ↑
     |
UserRepository
```

### ③ Bean lifecycle management

Spring can manage:

```text
Create
  ↓
Initialize
  ↓
Use
  ↓
Destroy
```

### ④ Configuration

Spring can manage configuration from:

* annotations
* Java configuration
* properties
* environment variables
* profiles

### ⑤ Event publishing

Spring applications can publish application events.

### ⑥ Resource management

It can provide access to application resources.

# 9. `ApplicationContext` vs `BeanFactory`

This is another common exam question.

Both are Spring IoC container abstractions:

```text
          BeanFactory
              ↑
              |
      ApplicationContext
```

`ApplicationContext` provides everything you'd expect from a BeanFactory plus additional application-oriented features.

| `BeanFactory`            | `ApplicationContext`                |
| ------------------------ | ----------------------------------- |
| Basic IoC container      | More complete application container |
| Bean creation/management | Bean creation/management            |
| Dependency injection     | Dependency injection                |
| Basic lifecycle          | Lifecycle support                   |
| Basic                    | Events                              |
| Basic                    | Internationalization                |
| Basic                    | Resource loading                    |
| Basic                    | Environment/profiles                |

For modern Spring applications:

> **`ApplicationContext` is generally the container you work with.**

# 10. Common implementations

`ApplicationContext` is an interface.

There are different implementations.

For annotation-based configuration:

```java
AnnotationConfigApplicationContext
```

For XML configuration:

```java
ClassPathXmlApplicationContext
```

For web applications, Spring provides web-specific application contexts.

You don't usually need to memorize every implementation for basic Spring development.

The important distinction is:

```text
ApplicationContext
       ↑
       |
   interface
       |
       +-- AnnotationConfigApplicationContext
       |
       +-- ClassPathXmlApplicationContext
       |
       +-- Web application contexts
```

# 11. Spring Boot and `ApplicationContext`

This is especially important.

In a normal Spring application, you might explicitly create:

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(...);
```

But in **Spring Boot**, you normally don't do this yourself.

For example:

```java
@SpringBootApplication
public class MyApplication {

    public static void main(String[] args) {

        SpringApplication.run(
            MyApplication.class,
            args
        );
    }
}
```

This:

```java
SpringApplication.run(...)
```

starts the Spring application and creates the application context.

Conceptually:

```text
SpringApplication.run()
          |
          ↓
Create ApplicationContext
          |
          ↓
Scan components
          |
          ↓
Create Beans
          |
          ↓
Resolve dependencies
          |
          ↓
Start application
```

This is one reason Spring Boot feels so simple.

# 12. How `ApplicationContext` fits into Spring Boot

A typical Spring Boot application:

```text
                   Spring Boot
                       |
                       ↓
              ApplicationContext
                       |
        +--------------+--------------+
        |              |              |
        ↓              ↓              ↓
   Controller       Service       Repository
        |              |              |
        +--------------+--------------+
                       |
                       ↓
                Dependency Injection
```

So don't think of Spring Boot and `ApplicationContext` as competing concepts.

Rather:

```text
Spring Boot
    ↓
starts/configures
    ↓
ApplicationContext
    ↓
manages
    ↓
Spring Beans
```

# 13. `getBean()`

You can retrieve a Bean from the context:

```java
UserService service =
    context.getBean(UserService.class);
```

You can also retrieve by name:

```java
UserService service =
    (UserService) context.getBean("userService");
```

The type-safe form is generally preferable:

```java
context.getBean(UserService.class);
```

However, in normal Spring application code, you usually **don't repeatedly call `getBean()`**.

Instead, let Spring inject dependencies:

```java
@Service
public class OrderService {

    private final UserService userService;

    public OrderService(UserService userService) {
        this.userService = userService;
    }
}
```

So:

```text
Bad/less typical application style:

service = context.getBean(...)


Preferred:

Spring
  ↓
inject dependency
  ↓
service
```

# 14. Why is `ApplicationContext` important?

It provides the infrastructure for **IoC and DI**.

Without it:

```text
Your code
   |
   +-- new A()
   +-- new B()
   +-- new C()
   +-- connect A → B
   +-- connect B → C
```

With it:

```text
ApplicationContext
   |
   +-- create A
   +-- create B
   +-- create C
   +-- wire A → B
   +-- wire B → C
   +-- manage lifecycle
```

Therefore, `ApplicationContext` is one of the central mechanisms that makes Spring's programming model possible.

---

# 15. Important distinction: Context ≠ configuration file

A common beginner misunderstanding is:

> "Is `ApplicationContext` the same thing as `application.properties`?"

No.

`application.properties` is configuration:

```properties
server.port=8080
```

`ApplicationContext` is the **Spring container** that manages Beans and application infrastructure.

```text
application.properties
       |
       | configuration
       ↓
Spring Boot
       |
       ↓
ApplicationContext
       |
       ↓
Beans
```

# 16. Exam-ready answer

If the exam asks:

> **What is an ApplicationContext?**

A strong answer is:

> **`ApplicationContext` is a central interface in the Spring Framework representing the IoC container. It is responsible for creating, configuring, and managing Spring Beans, resolving and injecting their dependencies, managing their lifecycle, and providing additional application services such as event publishing, resource loading, and environment/configuration support.**

For a shorter exam answer:

> **`ApplicationContext` is Spring's IoC container. It creates and manages Beans and their dependencies and provides application-level services such as configuration, lifecycle management, and event handling.**
