# What is the default Bean ID if you only use `@Bean`? How can you override this?

This topic is about **Spring Bean naming**.

The key idea:

> **When you use `@Bean` without specifying a name, Spring uses the method name as the default Bean ID. You can override it by providing a name or aliases in the `@Bean` annotation.**

In short:

```text
@Bean
public MyService myService()

        ↓

Bean ID:
"myService"
```

---

# 1. What is a Bean ID?

A **Bean ID** (also called Bean name) is the unique identifier of a Bean inside the Spring `ApplicationContext`.

Example:

```java
@Configuration
public class AppConfig {

    @Bean
    public UserService userService() {
        return new UserService();
    }
}
```

Spring registers:

```text
ApplicationContext

Bean ID:
    userService

Bean Type:
    UserService
```

You can think of it as a map:

```java
Map<String, Object> beans;
```

Internally:

```text
"userService"  →  UserService object
```

---

# 2. Default Bean ID with `@Bean`

Example:

```java
@Configuration
public class AppConfig {

    @Bean
    public PaymentService paymentService() {

        return new PaymentService();
    }
}
```

The Bean ID is:

```text
paymentService
```

Why?

Because:

```text
method name
        ↓
Bean ID
```

The rule:

```java
@Bean
public Type methodName()
```

creates:

```text
Bean ID = "methodName"
```

---

# 3. Example

Configuration:

```java
@Configuration
public class DatabaseConfig {


    @Bean
    public DataSource mysqlDataSource() {

        return new DataSource();
    }


    @Bean
    public DataSource postgresDataSource() {

        return new DataSource();
    }
}
```

Spring creates:

```text
Bean ID                     Type
---------------------------------------
mysqlDataSource             DataSource

postgresDataSource          DataSource
```

You can access them by name:

```java
ApplicationContext context;

DataSource ds =
    context.getBean("mysqlDataSource",
                    DataSource.class);
```

---

# 4. How to override the default Bean ID?

Use the `name` attribute of `@Bean`.

Example:

```java
@Configuration
public class AppConfig {


    @Bean(name = "mainUserService")
    public UserService userService() {

        return new UserService();
    }
}
```

Now:

Default:

```text
userService
```

becomes:

```text
mainUserService
```

The registration:

```text
ApplicationContext

"mainUserService"
          |
          ↓
   UserService object
```

---

# 5. Using multiple Bean names (aliases)

A Bean can have multiple IDs.

Example:

```java
@Configuration
public class AppConfig {


    @Bean(name = {
        "primaryService",
        "userService",
        "defaultService"
    })
    public UserService service() {

        return new UserService();
    }
}
```

Spring creates:

```text
Bean IDs:

primaryService
userService
defaultService

          |
          ↓

same UserService object
```

They are aliases.

---

# 6. Using `value` instead of `name`

`value` is an alias for `name`.

These are equivalent:

```java
@Bean(name = "myService")
public UserService service() {

}
```

and:

```java
@Bean("myService")
public UserService service() {

}
```

and:

```java
@Bean(value = "myService")
public UserService service() {

}
```

Most developers use:

```java
@Bean("myService")
```

for simplicity.

---

# 7. Bean ID and dependency injection

Usually, Spring injects by type:

```java
@Autowired
private UserService service;
```

Spring searches:

```text
Type:
UserService
```

But if there are multiple Beans:

```text
UserService

    |
    +--- userServiceA
    |
    +--- userServiceB
```

Spring cannot decide.

You can use Bean ID:

```java
@Autowired
@Qualifier("userServiceA")
private UserService service;
```

Now:

```text
@Autowired
        ↓
Find type

@Qualifier
        ↓
Find specific Bean ID
```

---

# 8. Bean ID with `@Component`

This is slightly different.

For:

```java
@Component
public class UserService {

}
```

The default Bean ID is usually:

```text
userService
```

Spring converts:

```text
Class name:
UserService

↓

Bean name:
userService
```

Rule:

```text
Class name first letter becomes lowercase
```

Examples:

```text
UserService
    ↓
userService


OrderController
    ↓
orderController
```

---

# 9. Difference between `@Bean` naming and `@Component` naming

|                      | `@Bean`         | `@Component`                |
| -------------------- | --------------- | --------------------------- |
| Bean name comes from | Method name     | Class name                  |
| Defined on           | Method          | Class                       |
| Default ID           | Method name     | Lower camel-case class name |
| Custom name          | `@Bean("name")` | `@Component("name")`        |

Example:

## `@Bean`

```java
@Bean
public UserService myService() {

}
```

Bean ID:

```text
myService
```

---

## `@Component`

```java
@Component
public class UserService {

}
```

Bean ID:

```text
userService
```

---

# 10. Why does Bean ID matter?

Usually you inject by type:

```java
@Autowired
UserService service;
```

You don't care about the name.

But names are important for:

## 1. Multiple implementations

Example:

```java
@Bean("mysql")
DataSource mysql(){

}

@Bean("oracle")
DataSource oracle(){

}
```

Injection:

```java
@Autowired
@Qualifier("mysql")
DataSource dataSource;
```

---

## 2. Accessing Beans manually

Example:

```java
UserService service =
    context.getBean(
        "userService",
        UserService.class);
```

---

## 3. Framework configuration

Spring Boot internally uses many named Beans:

Example:

```text
dataSource
entityManagerFactory
transactionManager
```

Names allow different parts of Spring to find each other.

---

# 11. Bean ID vs Java variable name

Important distinction.

Example:

```java
@Bean
public UserService createUserService() {

    return new UserService();
}
```

Bean ID:

```text
createUserService
```

NOT:

```text
userService
```

The method name matters.

---

# 12. Bean ID vs class name

Example:

```java
@Bean
public UserService accountService() {

    return new UserService();
}
```

The class is:

```text
UserService
```

but the Bean ID is:

```text
accountService
```

because:

```text
@Bean → method name
```

When Spring processes:

```java
@Bean("payment")
public PaymentService service() {

    return new PaymentService();

```

it creates something like:

```text
BeanDefinition

name:
    payment

class:
    PaymentService
```

Then:

```text
ApplicationContext

"payment"
      |
      ↓
PaymentService instance
```

# 14. Exam-ready answer

Question:

> **What is the default Bean ID if you only use `@Bean`? How can you override this?**

A strong answer:

> **When using `@Bean` without specifying a name, Spring uses the method name as the default Bean ID. For example, a method named `userService()` creates a Bean with the ID `userService`. The default name can be overridden using the `name` attribute of `@Bean`, such as `@Bean(name="myService")`. Multiple names can also be provided to create aliases.**

---

# 15. Short version to memorize

```text
@Bean
public UserService userService()

        ↓

Bean ID:
"userService"
```

Override:

```java
@Bean("mainService")
public UserService userService() {

}
```

Result:

```text
Bean ID:
"mainService"
```

Multiple aliases:

```java
@Bean({"main", "default", "primary"})
```

creates:

```text
main
default
primary
        |
        ↓
same Bean
```

The interview rule:

> **For `@Bean`, the default Bean ID is the method name. For `@Component`, the default Bean ID is the class name with the first letter lowercased.**
