This topic is about **when Spring creates Bean objects inside the `ApplicationContext`**.

The key exam question is:

> **Are Spring Beans lazily or eagerly instantiated by default? How do you change this behavior?**

The short answer:

> **Spring Beans are eagerly instantiated by default (for singleton Beans). You can change this behavior using lazy initialization with `@Lazy` or configuration properties.**

Let's explore this in detail.

---

# 1. What does "instantiation" mean?

Instantiation means:

> **When does Spring actually create the Java object?**

For example:

```java
@Component
public class UserService {

    public UserService() {
        System.out.println("UserService created");
    }
}
```

The question is:

When does this happen?

Option 1:

```text
ApplicationContext starts
        ↓
Spring creates UserService
        ↓
Application runs
```

This is **eager initialization**.

Option 2:

```text
ApplicationContext starts
        ↓
No UserService object yet
        ↓
First request needs UserService
        ↓
Spring creates UserService
```

This is **lazy initialization**.

---

# 2. Default behavior: eager initialization

By default, Spring creates **singleton Beans eagerly**.

Example:

```java
@Component
public class UserService {

    public UserService() {
        System.out.println("Creating UserService");
    }
}
```

When the `ApplicationContext` starts:

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(AppConfig.class);
```

Spring does:

```text
Start ApplicationContext
        ↓
Scan components
        ↓
Find UserService
        ↓
Create UserService Bean
        ↓
Store Bean in container
        ↓
Application ready
```

Output:

```
Creating UserService
```

even if nobody has requested `UserService` yet.

---

# 3. Why does Spring use eager initialization by default?

Because Spring wants to discover problems early.

For example:

```java
@Service
public class OrderService {

    public OrderService(PaymentService paymentService) {
        ...
    }
}
```

Suppose `PaymentService` is missing.

With eager initialization:

```text
Application startup
        ↓
Create OrderService
        ↓
Need PaymentService
        ↓
Cannot find dependency
        ↓
Startup fails
```

You discover the problem immediately.

This is usually desirable for enterprise applications.

---

# 4. Lazy initialization

Lazy initialization means:

> Spring creates the Bean only when it is first needed.

Example:

```java
@Component
@Lazy
public class ReportService {

    public ReportService() {
        System.out.println("Creating ReportService");
    }
}
```

Now:

```java
ApplicationContext context =
    new AnnotationConfigApplicationContext(AppConfig.class);

System.out.println("Application started");
```

Output:

```
Application started
```

No Bean creation yet.

Later:

```java
ReportService service =
    context.getBean(ReportService.class);
```

Now:

```
Creating ReportService
```

The lifecycle becomes:

```text
ApplicationContext starts
        ↓
Bean definition registered
        ↓
(no object created)
        ↓
getBean()
        ↓
create object
        ↓
initialize Bean
```

---

# 5. Using `@Lazy`

The most common way to make a Bean lazy is:

```java
@Component
@Lazy
public class HeavyService {

}
```

or:

```java
@Service
@Lazy
public class DatabaseService {

}
```

Now Spring delays creation.

---

# 6. Lazy injection with `@Lazy`

You can also make a dependency lazy.

Example:

```java
@Service
public class UserService {

    private final ReportService reportService;

    public UserService(
            @Lazy ReportService reportService) {

        this.reportService = reportService;
    }
}
```

Normally:

```text
UserService creation
        ↓
Create ReportService
```

With `@Lazy`:

```text
UserService creation
        ↓
Inject proxy
        ↓
Later when ReportService is used
        ↓
Create ReportService
```

Spring often uses a proxy object:

```text
UserService
     |
     ↓
ReportService Proxy
     |
     ↓
(real object created later)
```

---

# 7. Enable lazy initialization globally

Instead of annotating every Bean:

```java
@Lazy
@Component
class A {}

@Lazy
@Component
class B {}

@Lazy
@Component
class C {}
```

Spring Boot provides a global option.

In:

```
application.properties
```

write:

```properties
spring.main.lazy-initialization=true
```

Now:

```text
All singleton Beans
        ↓
lazy by default
```

Example:

```text
Application starts
        ↓
Bean definitions loaded
        ↓
No Bean objects created
        ↓
Beans created when requested
```

---

# 8. Disable lazy initialization globally

The default is:

```properties
spring.main.lazy-initialization=false
```

or simply omit the property.

Then:

```text
Singleton Beans
        ↓
Created during startup
```

---

# 9. Eager vs lazy comparison

|                         | Eager initialization | Lazy initialization |
| ----------------------- | -------------------- | ------------------- |
| Default Spring behavior | ✅ Yes                | No                  |
| Bean created            | Application startup  | First use           |
| Startup time            | Slower               | Faster              |
| First request           | Faster               | May be slower       |
| Finds errors early      | Yes                  | Later               |
| Memory usage            | Higher               | Lower initially     |

---

# 11. Important: singleton vs prototype scope

This question usually assumes **singleton Beans**.

Remember:

Spring default scope:

```java
@Scope("singleton")
```

A singleton Bean:

```text
One instance per ApplicationContext
```

So:

```text
Eager singleton:

Context startup
       ↓
One object created


Lazy singleton:

First request
       ↓
One object created
```

---

Prototype Beans behave differently:

```java
@Component
@Scope("prototype")
public class MyBean {
}
```

Prototype:

```text
Every request
       ↓
new object
```

Spring does not manage the complete lifecycle of prototype Beans.

---

# 12. Why might we use lazy initialization?

Lazy initialization can help when:

### 1. Large applications

Example:

```text
500 Beans
```

Creating everything at startup may take time.

Lazy:

```text
Start faster
Create only needed Beans
```

---

### 2. Optional features

Example:

```text
Reporting module
       |
       ↓
Only used once per month
```

No need to create it at startup.

---

### 3. Resource-heavy Beans

Examples:

* database connections
* external API clients
* large caches
* message consumers

---

# 13. Why might we avoid lazy initialization?

Because problems appear later.

Example:

```java
@Service
@Lazy
class PaymentService {

    PaymentService() {
        connectToPaymentGateway();
    }
}
```

Application starts:

```
OK
```

Later:

```
First payment request
        ↓
Connection failure
        ↓
Runtime error
```

With eager initialization:

```
Application startup
        ↓
Connection failure
        ↓
Application refuses to start
```

Many production systems prefer failing early.

---

# 14. Spring Boot recommendation

Modern Spring Boot applications usually keep the default:

```properties
spring.main.lazy-initialization=false
```

because:

* startup failures are detected immediately
* configuration problems are found early
* production behavior is more predictable

Enable lazy initialization only when startup time is a problem.

---

# 15. Exam-ready answer

Question:

> **Are beans lazily or eagerly instantiated by default? How do you alter this behavior?**

Good answer:

> **Spring Beans are eagerly instantiated by default for singleton scope. When the `ApplicationContext` is created, Spring creates and initializes singleton Beans immediately. Lazy initialization can be enabled using `@Lazy` on a Bean or configuration class, or globally in Spring Boot using `spring.main.lazy-initialization=true`. With lazy initialization, Beans are created only when they are first requested.**
