This topic follows naturally from the **Spring Bean lifecycle** you just learned. Closing the `ApplicationContext` is the final part of that lifecycle because Spring needs to give Beans a chance to clean up resources.

# 1. Why do we need to close an `ApplicationContext`?

Recall the Bean lifecycle:

```text
Create Bean
    ↓
Inject dependencies
    ↓
Initialize
    ↓
Use Bean
    ↓
Destroy Bean
```

When the application shuts down, Spring should perform the last step:

```text
ApplicationContext
       │
       │ close
       ▼
@PreDestroy
       ↓
destroy callbacks
       ↓
Beans destroyed
       ↓
resources released
```

For example, a Bean might own:

* database connections
* thread pools
* network connections
* file resources
* background tasks

So properly closing the context allows Spring to perform cleanup.

---

# 2. Preferred way: call `close()`

If you created a context manually, the preferred approach is to close it explicitly.

For example:

```java
AnnotationConfigApplicationContext context =
        new AnnotationConfigApplicationContext(AppConfig.class);

try {
    // use the application
} finally {
    context.close();
}
```

`AnnotationConfigApplicationContext` implements `ConfigurableApplicationContext`, which provides:

```java
context.close();
```

So the important API is:

```java
ConfigurableApplicationContext
```

and its:

```java
close()
```

method.

---

# 3. Why `ConfigurableApplicationContext`?

This is a useful Java interface concept.

You might have:

```java
ApplicationContext context =
        new AnnotationConfigApplicationContext(AppConfig.class);
```

`ApplicationContext` provides the general Spring container functionality.

But if you need lifecycle operations such as closing the context, you can use:

```java
ConfigurableApplicationContext
```

For example:

```java
ConfigurableApplicationContext context =
        new AnnotationConfigApplicationContext(AppConfig.class);

context.close();
```

Conceptually:

```text
ApplicationContext
       │
       │ general container functionality
       ▼
ConfigurableApplicationContext
       │
       │ + lifecycle control
       ▼
     close()
```

---

# 4. What happens when you call `close()`?

Suppose you have:

```java
@Component
public class MyBean {

    @PreDestroy
    public void cleanup() {
        System.out.println("Cleaning up...");
    }
}
```

Then:

```java
context.close();
```

causes Spring to shut down the context and invoke appropriate destruction callbacks.

Conceptually:

```text
context.close()
      ↓
Spring begins shutdown
      ↓
@PreDestroy
      ↓
destroy callbacks
      ↓
Beans destroyed
      ↓
ApplicationContext closed
```

So `close()` is not simply "delete the Java objects."

It tells Spring:

> **"The container is shutting down; perform your managed shutdown and cleanup operations."**

---

# 5. What about Spring Boot?

This is the particularly important part of the exam question:

> **Does Spring Boot do this for you?**

### Yes.

In a normal Spring Boot application, **Spring Boot manages the `ApplicationContext` lifecycle and normally closes it when the application is shutting down.**

For example:

```java
@SpringBootApplication
public class Application {

    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

You normally don't need:

```java
context.close();
```

in your `main()` method.

Spring Boot starts the application context:

```text
SpringApplication.run()
        ↓
ApplicationContext
        ↓
Application runs
        ↓
Shutdown signal
        ↓
Spring Boot/Spring closes context
        ↓
Bean destruction callbacks
```

---

# 6. How does Spring Boot know when to shut down?

For a typical standalone Spring Boot application, the application is running inside a process.

When the application receives a normal shutdown signal, Spring's shutdown mechanism closes the application context.

For example:

```text
Ctrl + C
   ↓
shutdown signal
   ↓
Spring Boot shutdown
   ↓
ApplicationContext.close()
   ↓
@PreDestroy
   ↓
resources released
```

This is why you normally don't have to write cleanup code in `main()` such as:

```java
context.close();
```

Spring Boot handles the application lifecycle for you.

---

# 7. What about `@PreDestroy`?

This connects directly to the previous topic.

You can define cleanup logic:

```java
@Component
public class MyService {

    @PostConstruct
    public void init() {
        System.out.println("Starting...");
    }

    @PreDestroy
    public void destroy() {
        System.out.println("Stopping...");
    }
}
```

Normal lifecycle:

```text
Application starts
      ↓
@PostConstruct
      ↓
Application runs
      ↓
Shutdown
      ↓
@PreDestroy
      ↓
Bean destroyed
```

So:

```text
@PostConstruct → startup initialization

@PreDestroy    → shutdown cleanup
```

---

# 8. What about integration tests?

This is particularly relevant to the previous question.

If you have:

```java
@SpringBootTest
class MyIntegrationTest {

    @Autowired
    ApplicationContext context;

}
```

you normally **don't manually close the context**.

Spring's test framework manages the test `ApplicationContext` lifecycle and can cache contexts between tests.

Conceptually:

```text
@SpringBootTest
      ↓
Spring Test creates context
      ↓
run tests
      ↓
Spring Test manages context
      ↓
context eventually closed
```

So don't normally do this:

```java
context.close();
```

inside each test method.

You could interfere with the context lifecycle and context caching.

---

# 9. Three situations to remember

| Situation                             | Who closes the context?                 |
| ------------------------------------- | --------------------------------------- |
| Manually created `ApplicationContext` | **You** should close it                 |
| Normal Spring Boot application        | **Spring Boot/Spring** manages shutdown |
| `@SpringBootTest` integration test    | **Spring Test** manages the context     |

This is probably the most useful table for your exam.

---

# 10. Manual application vs Spring Boot

### Manual Spring

```java
ConfigurableApplicationContext context =
        new AnnotationConfigApplicationContext(AppConfig.class);

try {
    // application
} finally {
    context.close();
}
```

You are responsible for the context you created.

### Spring Boot

```java
@SpringBootApplication
public class Application {

    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

You normally **don't manually close it**.

Spring Boot manages the lifecycle.

# 11. Why is this related to IoC?

This is actually a nice demonstration of the meaning of **IoC**.

Without a container:

```text
Your code
   │
   ├── creates objects
   ├── initializes objects
   ├── manages objects
   └── destroys objects
```

With Spring:

```text
              Spring IoC Container
                     │
       ┌─────────────┼─────────────┐
       ▼             ▼             ▼
    Create       Initialize     Destroy
       │             │             │
       └─────────────┼─────────────┘
                     ▼
                Spring Bean
```

Spring isn't merely helping you with `new`.

It takes responsibility for the **object lifecycle**.

# 12. Exam-ready answer

If your examiner asks:

> **What is the preferred way to close an application context? Does Spring Boot do this for you?**

A good answer is:

> **If I create an `ApplicationContext` manually, I should close it using `ConfigurableApplicationContext.close()`, preferably in a `finally` block or equivalent resource-management structure. Closing the context allows Spring to perform Bean destruction callbacks such as `@PreDestroy`. In a normal Spring Boot application, I don't usually need to close the context manually. Spring Boot manages the application lifecycle and closes the `ApplicationContext` during normal application shutdown.**

### Short version to memorize

```text
Manual context → context.close()

Spring Boot    → normally closes it for you

Integration test → Spring Test manages it
```

And the conceptual lifecycle is:

```text
Application starts
      ↓
Create Beans
      ↓
Initialize Beans
      ↓
Application runs
      ↓
Shutdown
      ↓
Close ApplicationContext
      ↓
@PreDestroy
      ↓
Destroy Beans
```

**The key idea:** `ApplicationContext.close()` is the signal to Spring that **the container is shutting down and its managed Beans should be cleaned up properly**.
