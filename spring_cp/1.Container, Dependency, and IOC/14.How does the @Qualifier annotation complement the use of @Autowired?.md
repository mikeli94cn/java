# How does the `@Qualifier` annotation complement the use of `@Autowired`?

This topic is about **how Spring resolves dependency injection when multiple Beans of the same type exist**.

The key idea:

> **`@Autowired` tells Spring "inject a Bean of this type"; `@Qualifier` tells Spring "inject this specific Bean when there are multiple candidates of the same type."**

In short:

```text
@Autowired
        |
        ↓
Find Bean by type

@Qualifier
        |
        ↓
Choose a specific Bean among matching types
```

---

# 1. The problem: multiple Beans of the same type

Normally, `@Autowired` works by type.

Example:

```java
public interface PaymentService {

    void pay();

}
```

Two implementations:

```java
@Service
public class CreditCardPaymentService 
        implements PaymentService {

    public void pay() {
        System.out.println("Credit card payment");
    }
}
```

```java
@Service
public class PaypalPaymentService 
        implements PaymentService {

    public void pay() {
        System.out.println("PayPal payment");
    }
}
```

Now Spring has:

```text
ApplicationContext

PaymentService
      |
      +---- CreditCardPaymentService
      |
      +---- PaypalPaymentService
```

---

# 2. What happens with only `@Autowired`?

Example:

```java
@Service
public class OrderService {

    @Autowired
    private PaymentService paymentService;

}
```

Spring sees:

```text
Need:
    PaymentService

Found:
    CreditCardPaymentService
    PaypalPaymentService
```

Spring cannot decide.

Result:

```
NoUniqueBeanDefinitionException
```

Example error:

```
expected single matching bean but found 2
```

---

# 3. Solution: add `@Qualifier`

`@Qualifier` narrows the selection.

Example:

```java
@Service
public class OrderService {

    @Autowired
    @Qualifier("creditCardPaymentService")
    private PaymentService paymentService;

}
```

Now Spring knows:

```text
Need:
    PaymentService

Choose:
    creditCardPaymentService
```

The injection becomes:

```text
OrderService
       |
       ↓
CreditCardPaymentService
```

---

# 4. Where does the qualifier name come from?

By default, Spring uses the Bean name.

Example:

```java
@Service
public class CreditCardPaymentService 
        implements PaymentService {

}
```

The default Bean name is:

```text
creditCardPaymentService
```

because Spring converts the class name:

```
CreditCardPaymentService
          ↓
creditCardPaymentService
```

Therefore:

```java
@Qualifier("creditCardPaymentService")
```

matches that Bean.

---

# 5. Using `@Qualifier` with constructor injection

Modern Spring applications usually prefer constructor injection.

Example:

```java
@Service
public class OrderService {

    private final PaymentService paymentService;


    public OrderService(
        @Qualifier("creditCardPaymentService")
        PaymentService paymentService) {

        this.paymentService = paymentService;
    }
}
```

The dependency is clear:

```text
OrderService
       |
       ↓
CreditCardPaymentService
```

---

# 6. Defining custom qualifier names

Instead of relying on class names:

```java
@Service("credit")
public class CreditCardPaymentService
        implements PaymentService {

}
```

```java
@Service("paypal")
public class PaypalPaymentService
        implements PaymentService {

}
```

Now inject:

```java
@Service
public class OrderService {

    private final PaymentService paymentService;


    public OrderService(
        @Qualifier("paypal")
        PaymentService paymentService) {

        this.paymentService = paymentService;
    }
}
```

Spring chooses:

```text
paypal
   ↓
PaypalPaymentService
```

# 7. `@Qualifier` with `@Bean`

`@Qualifier` is also used with configuration classes.

Example:

```java
@Configuration
public class PaymentConfig {


    @Bean
    @Qualifier("credit")
    public PaymentService creditPayment() {

        return new CreditCardPaymentService();
    }


    @Bean
    @Qualifier("paypal")
    public PaymentService paypalPayment() {

        return new PaypalPaymentService();
    }
}
```

Injection:

```java
@Service
public class OrderService {


    public OrderService(
        @Qualifier("paypal")
        PaymentService service) {

        this.service = service;
    }
}
```

# 8. `@Autowired` + `@Qualifier` relationship

Think of it like a two-step process:

## Step 1: `@Autowired`

Find candidates by type.

Example:

```java
@Autowired
PaymentService service;
```

Spring searches:

```
PaymentService beans
```

Result:

```
CreditCardPaymentService
PaypalPaymentService
```

---

## Step 2: `@Qualifier`

Filter candidates.

Example:

```java
@Qualifier("paypal")
```

Result:

```
PaypalPaymentService
```

---

The complete process:

```text
@Autowired

       ↓

Find all Beans matching type

       ↓

Multiple candidates?

       ↓

Use @Qualifier

       ↓

Inject selected Bean
```

---

# 9. `@Qualifier` vs `@Primary`

These two are often compared.

Suppose:

```java
@Service
public class CreditCardPaymentService
        implements PaymentService {

}
```

```java
@Service
@Primary
public class PaypalPaymentService
        implements PaymentService {

}
```

Now:

```java
@Autowired
PaymentService service;
```

Spring chooses:

```
PaypalPaymentService
```

because it is `@Primary`.

---

## Difference

|         | `@Primary`                    | `@Qualifier`                               |
| ------- | ----------------------------- | ------------------------------------------ |
| Purpose | Default choice                | Explicit choice                            |
| Scope   | Global preference             | Specific injection point                   |
| Usage   | One Bean preferred everywhere | Choose different Beans in different places |

---

Example:

Default:

```java
@Primary
@Service
class PaypalPaymentService
```

Most places:

```java
@Autowired
PaymentService service;
```

gets:

```
PaypalPaymentService
```

But one place:

```java
@Autowired
@Qualifier("creditCardPaymentService")
PaymentService service;
```

gets:

```
CreditCardPaymentService
```

---

# 10. `@Qualifier` with collections

A useful advanced feature:

Suppose:

```java
@Service("email")
class EmailNotificationService
        implements NotificationService {

}


@Service("sms")
class SmsNotificationService
        implements NotificationService {

}
```

Inject all:

```java
@Autowired
private List<NotificationService> services;
```

Spring injects:

```text
[
 EmailNotificationService,
 SmsNotificationService
]
```

---

You can filter:

```java
@Autowired
@Qualifier("email")
private NotificationService service;
```

Only:

```
EmailNotificationService
```

# 12. Custom qualifier annotations

For large projects, string names can become error-prone.

Instead:

```java
@Target({
    ElementType.FIELD,
    ElementType.PARAMETER,
    ElementType.TYPE
})
@Retention(RetentionPolicy.RUNTIME)
@Qualifier
public @interface OnlinePayment {

}
```

Use:

```java
@OnlinePayment
@Service
public class PaypalPaymentService
        implements PaymentService {

}
```

Injection:

```java
public OrderService(
        @OnlinePayment PaymentService service) {

}
```

This is cleaner for enterprise applications.

# 13. Common interview mistakes

## Question:

> Does `@Qualifier` replace `@Autowired`?

Answer:

No.

They work together.

```text
@Autowired
    |
    ↓
Request dependency injection

@Qualifier
    |
    ↓
Resolve ambiguity
```

---

## Question:

> Can you use `@Qualifier` without `@Autowired`?

Yes.

Example:

```java
@Resource(name="paypal")
PaymentService service;
```

or with constructor injection:

```java
public OrderService(
    @Qualifier("paypal")
    PaymentService service) {

}
```

# 14. Exam-ready answer

Question:

> **How does the `@Qualifier` annotation complement the use of `@Autowired`?**

A strong answer:

> **`@Autowired` performs dependency injection by searching the Spring ApplicationContext for a Bean matching the required type. If multiple Beans of the same type exist, Spring cannot determine which one to inject and throws a `NoUniqueBeanDefinitionException`. The `@Qualifier` annotation resolves this ambiguity by specifying the name of the Bean that should be injected. It is commonly used together with `@Autowired` on fields, constructors, or methods.**

---

# 15. Short version to memorize

```text
@Autowired
        ↓
Find Bean by type


Multiple Beans?
        ↓

@Qualifier
        ↓
Choose one Bean
```

Example:

```java
public OrderService(
    @Qualifier("paypal")
    PaymentService service) {

}
```

means:

> "Inject the `PaymentService` Bean whose qualifier is `paypal`."

This is a key Spring DI concept because real enterprise applications frequently have **multiple implementations of the same interface**.
