# What does the `@Bean` annotation do?

This topic is about **explicit Bean registration in Spring**.

The key idea:

> **`@Bean` tells Spring that the object returned by a method should be registered as a Bean in the `ApplicationContext` and managed by the Spring IoC container.**

In simple words:

```text
@Bean
        ↓
Create object
        ↓
Register object in Spring container
        ↓
Manage its lifecycle
        ↓
Allow dependency injection
```

---

# 1. Why do we need `@Bean`?

Spring manages objects called **Beans**.

Normally, Spring discovers Beans through component scanning:

```java
@Component
@Service
@Repository
@Controller
```

Example:

```java
@Service
public class UserService {

}
```

Spring automatically finds it:

```text
Component Scan
       |
       ↓
UserService
       |
       ↓
Spring Bean
```

But what about classes that:

* come from third-party libraries?
* cannot be modified?
* require custom construction logic?

Example:

```java
ObjectMapper mapper = new ObjectMapper();
```

You cannot add:

```java
@Component
public class ObjectMapper {

}
```

because you do not own the class.

The solution:

```java
@Bean
```

---

# 2. Basic usage of `@Bean`

Example:

```java
@Configuration
public class AppConfig {


    @Bean
    public UserService userService() {

        return new UserService();
    }

}
```

Spring does:

```text
AppConfig

      |
      ↓

@Bean method

      |
      ↓

new UserService()

      |
      ↓

Register UserService Bean
```

Now you can inject it:

```java
@Service
public class OrderService {


    private final UserService userService;


    public OrderService(UserService userService) {

        this.userService = userService;
    }

}
```

Spring provides the Bean automatically.

---

# 3. `@Bean` works inside `@Configuration`

Normally:

```java
@Configuration
public class AppConfig {

    @Bean
    public UserRepository repository() {

        return new UserRepository();
    }
}
```

`@Configuration` tells Spring:

> This class contains Bean definitions.

The relationship:

```text
@Configuration

        |
        ↓

@Bean methods

        |
        ↓

BeanDefinitions

        |
        ↓

ApplicationContext
```

# 4. What happens internally?

Consider:

```java
@Configuration
public class DatabaseConfig {


    @Bean
    public DataSource dataSource() {

        return new DataSource();
    }
}
```

During startup:

### Step 1: Spring finds configuration class

```text
DatabaseConfig
```

---

### Step 2: Reads `@Bean` methods

Spring creates:

```text
BeanDefinition:

name:
    dataSource

class:
    DataSource
```

---

### Step 3: Creates Bean

Later:

```java
new DataSource();
```

---

### Step 4: Registers it

```text
ApplicationContext

        |
        ↓

dataSource Bean
```

# 5. `@Bean` vs `new`

Important concept:

Without Spring:

```java
public class OrderService {


    private UserRepository repository =
            new UserRepository();

}
```

Your class controls object creation.

This is:

```text
Traditional programming
```

---

With Spring:

```java
@Bean
public UserRepository repository() {

    return new UserRepository();
}
```

Spring controls creation.

This is:

```text
Inversion of Control (IoC)
```

# 6. `@Bean` vs `@Component`

This is a very common interview question.

Both create Spring Beans, but the way is different.

---

## `@Component`

The class declares itself as a Bean.

Example:

```java
@Component
public class EmailService {

}
```

Spring:

```text
Component Scan
        |
        ↓
Find EmailService
        |
        ↓
Create Bean
```

---

## `@Bean`

The configuration class declares the Bean.

Example:

```java
@Configuration
public class AppConfig {


    @Bean
    public EmailService emailService() {

        return new EmailService();
    }
}
```

Spring:

```text
@Configuration
        |
        ↓
@Bean method
        |
        ↓
Create Bean
```

---

Comparison:

|                           | `@Component`       | `@Bean`                     |
| ------------------------- | ------------------ | --------------------------- |
| Location                  | Class              | Method                      |
| Discovery                 | Component scanning | Configuration parsing       |
| Control                   | Less control       | More control                |
| Use case                  | Your own classes   | Third-party/custom creation |
| Constructor customization | Limited            | Full control                |

---

# 7. When should you use `@Bean`?

## Case 1: Third-party classes

Example:

Jackson:

```java
ObjectMapper mapper =
        new ObjectMapper();
```

Configuration:

```java
@Configuration
public class JacksonConfig {


    @Bean
    public ObjectMapper objectMapper() {

        return new ObjectMapper();
    }

}
```

Now:

```java
@Autowired
ObjectMapper mapper;
```

works.

---

## Case 2: Custom initialization

Example:

```java
@Bean
public DataSource dataSource() {

    DataSource ds = new DataSource();

    ds.setUrl(
       "jdbc:mysql://localhost/test");

    return ds;
}
```

You control construction.

---

## Case 3: Conditional configuration

Example:

```java
@Bean
@ConditionalOnMissingBean
public PaymentService paymentService(){

    return new DefaultPaymentService();
}
```

Spring creates it only when needed.

# 8. Bean naming with `@Bean`

By default:

```java
@Bean
public UserService userService() {

    return new UserService();
}
```

Bean name:

```text
userService
```

The method name becomes the Bean name.

---

You can customize:

```java
@Bean("mainUserService")
public UserService userService(){

    return new UserService();
}
```

Now:

```text
Bean name:
    mainUserService
```

---

Injection:

```java
@Autowired
@Qualifier("mainUserService")
UserService service;
```

---

# 9. `@Bean` lifecycle management

Beans created by `@Bean` are fully managed by Spring.

Example:

```java
@Configuration
public class AppConfig {


    @Bean(initMethod = "start",
          destroyMethod = "stop")
    public Server server(){

        return new Server();
    }
}
```

Lifecycle:

```text
Create Bean

      ↓

Dependency Injection

      ↓

initMethod()

      ↓

Bean ready

      ↓

destroyMethod()
```

---

# 10. Bean scope with `@Bean`

By default:

```java
@Bean
```

creates:

```text
singleton
```

Example:

```java
@Bean
public UserService userService(){

    return new UserService();
}
```

Spring creates:

```text
One object
shared everywhere
```

---

You can change scope:

```java
@Bean
@Scope("prototype")
public UserService userService(){

    return new UserService();
}
```

Now:

```text
New object each request
```

---

# 11. Dependency injection between `@Bean` methods

Example:

```java
@Configuration
public class AppConfig {


    @Bean
    public UserRepository repository(){

        return new UserRepository();
    }


    @Bean
    public UserService service(
            UserRepository repository){

        return new UserService(repository);
    }

}
```

Spring resolves:

```text
UserRepository Bean

        ↓

UserService Bean
```

---

# 12. Important: `@Configuration` vs normal class

Consider:

```java
public class AppConfig {


    @Bean
    public User user(){

        return new User();
    }


    @Bean
    public Order order(){

        return new Order(user());
    }
}
```

With:

```java
@Configuration
```

Spring manages method calls.

It ensures:

```text
user()
      |
      ↓
same singleton Bean
```

Without `@Configuration`:

```text
user()
      |
      ↓
new User()
```

may create multiple objects.

# 15. Exam-ready answer

Question:

> **What does the `@Bean` annotation do?**

A strong answer:

> **The `@Bean` annotation is used inside a Spring configuration class to explicitly declare a method that produces a Spring-managed Bean. The object returned by the method is registered in the ApplicationContext and managed by Spring, including dependency injection and lifecycle management. It is commonly used when configuring third-party classes or when custom object creation logic is required.**

---

# 16. Short version to memorize

```text
@Bean

Method returns object

        ↓

Spring registers object

        ↓

Object becomes a Bean

        ↓

Spring manages lifecycle and injection
```

The most important comparison:

```text
@Component
    = "Spring, discover this class"

@Bean
    = "Spring, use this method's returned object"
```

In real Spring Boot applications, you will usually see:

* `@Component` / `@Service` for your own application classes
* `@Bean` for framework configuration, libraries, and customized objects
