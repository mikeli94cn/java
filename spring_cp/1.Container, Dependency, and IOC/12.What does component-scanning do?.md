# What does component-scanning do?

This topic is one of the foundations of Spring IoC. It explains **how Spring discovers your classes and automatically creates Beans from them**.

The key idea:

> **Component scanning tells Spring where to search for classes annotated with Spring stereotypes (`@Component`, `@Service`, `@Repository`, `@Controller`) and automatically register them as Beans in the ApplicationContext.**

In one sentence:

> **Component scanning converts annotated Java classes into Spring-managed Beans.**

---

# 1. The problem before component scanning

Without component scanning, you have to manually define every Bean.

Example:

```java
public class UserService {

}
```

You would need:

```java
@Configuration
public class AppConfig {

    @Bean
    public UserService userService() {
        return new UserService();
    }
}
```

The relationship:

```text
@Configuration
       |
       ↓
@Bean
       |
       ↓
UserService Bean
```

For a large application:

```text
500 classes
      ↓
500 @Bean methods
```

This becomes tedious.

Spring introduced **component scanning** to solve this.

---

# 2. What does component scanning do?

Component scanning performs these steps:

```text
ApplicationContext starts
          |
          ↓
Scan configured packages
          |
          ↓
Find annotated classes
          |
          ↓
Create BeanDefinitions
          |
          ↓
Register Beans
          |
          ↓
Create Bean instances
```

Example:

```text
com.example
      |
      ├── controller
      │       └── UserController.java
      |
      ├── service
      │       └── UserService.java
      |
      └── repository
              └── UserRepository.java
```

Spring scans:

```text
com.example
```

finds:

```java
@Controller
class UserController
```

```java
@Service
class UserService
```

```java
@Repository
class UserRepository
```

and registers them as Beans.

---

# 3. Component scanning annotations

Spring provides several stereotype annotations.

## `@Component`

The general-purpose annotation.

Example:

```java
@Component
public class EmailSender {

}
```

Spring creates:

```text
EmailSender Bean
```

---

## `@Service`

Used for business logic.

Example:

```java
@Service
public class UserService {

}
```

Internally:

```java
@Service
        ↓
@Component
```

It is basically a specialized component.

---

## `@Repository`

Used for data access.

Example:

```java
@Repository
public class UserRepository {

}
```

It also provides additional Spring exception translation features.

---

## `@Controller`

Used for MVC controllers.

Example:

```java
@Controller
public class UserController {

}
```

---

The relationship:

```text
              @Component

                  ▲

       ┌──────────┼──────────┐
       │          │          │
       ▼          ▼          ▼
   @Service  @Repository @Controller
```

All of them are detected by component scanning.

---

# 4. How do you enable component scanning?

There are several ways.

---

# Method 1: `@ComponentScan`

The traditional Spring way.

Example:

```java
@Configuration
@ComponentScan("com.example")
public class AppConfig {

}
```

Meaning:

> Scan the package `com.example` and find Spring components.

---

Example:

Directory:

```text
com.example
     |
     ├── UserService.java
     └── UserRepository.java
```

Code:

```java
@Service
public class UserService {

}
```

```java
@Repository
public class UserRepository {

}
```

Spring finds them automatically.

---

# Method 2: Spring Boot automatically enables scanning

In Spring Boot:

```java
@SpringBootApplication
public class Application {

    public static void main(String[] args) {

        SpringApplication.run(
            Application.class,
            args);
    }
}
```

`@SpringBootApplication` includes:

```java
@ComponentScan
```

It is actually a combination of:

```text
@SpringBootApplication
        |
        +── @SpringBootConfiguration
        |
        +── @EnableAutoConfiguration
        |
        +── @ComponentScan
```

Therefore:

```java
@SpringBootApplication
class Application {

}
```

automatically scans components.

---

# 5. Where does Spring scan by default?

Important exam point.

Suppose:

```java
package com.example.app;

@SpringBootApplication
public class Application {

}
```

Spring scans:

```text
com.example.app
       |
       ├── controller
       ├── service
       └── repository
```

and all sub-packages.

Example:

```
com.example.app
      |
      +-- service       ✅ scanned
      |
      +-- repository    ✅ scanned


com.example.other
      |
      +-- service       ❌ not scanned
```

The default rule:

> Spring scans the package where the main application class is located and all child packages.

---

# 6. Customizing component scanning

You can specify packages:

```java
@Configuration
@ComponentScan(
    basePackages = {
        "com.example.service",
        "com.example.repository"
    }
)
public class AppConfig {

}
```

Now Spring only scans those packages.

---

# 7. What happens internally?

Component scanning is not directly creating objects.

It first creates **BeanDefinitions**.

The flow:

```text
@Service
public class UserService {

}
```

↓

Scanner finds the annotation.

↓

Creates:

```text
BeanDefinition

class:
    UserService

scope:
    singleton
```

↓

Registers it:

```text
ApplicationContext
        |
        ↓
BeanFactory
        |
        ↓
UserService BeanDefinition
```

↓

Later:

```text
BeanDefinition
        ↓
create object
        ↓
UserService Bean
```

---

# 8. Component scanning and dependency injection

Component scanning usually works together with dependency injection.

Example:

```java
@Repository
public class UserRepository {

}
```

```java
@Service
public class UserService {

    private final UserRepository repository;


    public UserService(UserRepository repository) {
        this.repository = repository;
    }
}
```

Startup:

```text
Component Scan
        |
        ↓
Find UserRepository
        |
        ↓
Find UserService
        |
        ↓
Create Beans
        |
        ↓
Dependency Injection
        |
        ↓
UserService receives UserRepository
```

Without component scanning:

```text
UserRepository
        |
        X
not registered as Bean
```

Injection fails.

# 9. Component scanning vs `@Bean`

This is a common interview comparison.

## Component scanning

Class controls itself:

```java
@Service
public class UserService {

}
```

Spring discovers it automatically.

---

## `@Bean`

Configuration class controls creation:

```java
@Configuration
public class AppConfig {

    @Bean
    public UserService userService() {
        return new UserService();
    }
}
```

---

Comparison:

|                         | Component scanning             | `@Bean`                          |
| ----------------------- | ------------------------------ | -------------------------------- |
| Who creates definition? | Scanner                        | Configuration class              |
| Typical use             | Application classes            | External libraries/configuration |
| Annotation required     | `@Component`, `@Service`, etc. | `@Bean`                          |
| Less code               | ✅                              | ❌                                |

---

# 10. When should you use `@Bean` instead?

Component scanning is not always suitable.

Example:

A third-party class:

```java
public class ObjectMapper {

}
```

You cannot modify it:

```java
@Component
public class ObjectMapper {

}
```

because you don't own the source code.

Instead:

```java
@Configuration
public class AppConfig {

    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper();
    }
}
```

Now Spring manages it.

# 12. Common problems

## Problem 1: Bean not found

Example:

```
NoSuchBeanDefinitionException
```

Possible reason:

Your package is not scanned.

Example:

```
com.example.app.Application

com.other.service.UserService
```

`UserService` is outside the scan path.

Solution:

```java
@ComponentScan("com.other")
```

---

## Problem 2: Multiple Beans found

Example:

```
NoUniqueBeanDefinitionException
```

Two classes:

```java
@Service
class UserServiceA {}

@Service
class UserServiceB {}
```

Spring finds:

```text
UserServiceA
UserServiceB
```

but does not know which one to inject.

Solutions:

* `@Primary`
* `@Qualifier`

---

# 13. The relationship with IoC

Component scanning is a mechanism that enables IoC.

Without Spring:

```text
Your code
   |
   ↓
new UserService()
```

With component scanning:

```text
Spring
   |
   ↓
find UserService
   |
   ↓
create Bean
   |
   ↓
inject dependencies
   |
   ↓
manage lifecycle
```

The control moves from your code to Spring.

That is **Inversion of Control**.

---

# 14. Exam-ready answer

Question:

> **What does component-scanning do?**

A strong answer:

> **Component scanning is a Spring mechanism that searches specified packages for classes annotated with stereotypes such as `@Component`, `@Service`, `@Repository`, and `@Controller`. When these classes are found, Spring creates BeanDefinitions and registers them with the ApplicationContext so that they can be instantiated, injected, and managed as Spring Beans. In Spring Boot, component scanning is enabled automatically through `@SpringBootApplication`.**
