In Java, a String represents a sequence of characters. It is one of the most widely used data types, and unlike basic primitives, it is a full-featured object belonging to the built-in java.lang.String class.

The single most critical rule to remember about strings is that they are immutable. Once a string object is created on the heap, its text content can never be modified. Any action that appears to change a string actually creates a brand-new string object behind the scenes.

## 1. Creating Strings
There are two primary ways to instantiate a string object in Java, and they handle memory differently:
### Method A: String Literals (The String Pool)
This is the standard and recommended way. Java optimizes memory by storing literals in a special zone of the heap called the String Pool. If you create a new string literal that already exists in the pool, Java reuses the existing reference instead of allocating new memory.
```java
String str1 = "Hello"; 
String str2 = "Hello"; // Pointed to the exact same "Hello" object in the pool!
```
### Method B: Using the new Keyword
This forces the Java Virtual Machine (JVM) to bypass the String Pool optimization and allocate a brand-new, independent string object elsewhere on the heap.
```java
String str3 = new String("Hello"); // Distinct memory location from str1 and str2!
```

## 2. Manipulating Strings (Common Methods)
Because strings are immutable, none of these methods modify the original string container. Instead, they perform their action and return a completely new string object containing the result.
### Examining and Searching Text

* length(): Returns the total number of characters in the string.
* charAt(int index): Extracts a single character at a specific zero-based index location.
* indexOf(String str): Finds the starting index coordinate of a substring (returns -1 if not found).
```java
String text = "Java Development";
System.out.println(text.length());      // Outputs: 16
System.out.println(text.charAt(2));     // Outputs: v
System.out.println(text.indexOf("Dev")); // Outputs: 5
```
### Altering and Extracting Text

* substring(int beginIndex, int endIndex): Pulls out a smaller section of text starting at the beginIndex up to (but not including) the endIndex.
* toLowerCase() / toUpperCase(): Converts the entire sequence casing.
* replace(char old, char new): Swaps matching characters with alternative text.
* trim(): Strips out leading and trailing whitespaces from both ends of the text.
```java
String phrase = "  Code Now  ";
String upperClean = phrase.trim().toUpperCase(); // Method chaining
System.out.println(upperClean); // Outputs: "CODE NOW"

String domain = "example.com";
System.out.println(domain.substring(0, 7)); // Outputs: example
```

## Summary Rules & Behavior

| Method Call | Does it change the original variable? | What does it actually return? |
|---|---|---|
| str.toUpperCase(); | No. Original string stays lowercase. | A brand-new uppercase string object. |
| str.concat("!"); | No. Original text is untouched. | A combined text sequence object. |
| str.length(); | No. | A primitive int tracking character capacity. |


## 3. The Concatenation Performance Trap
You can combine strings using the + operator (e.g., "Java" + " 21"). However, using the + operator inside a loop is a significant performance bug:
```java
// ❌ BAD PERFORMANCE PRACTICE
String numbers = "";for (int i = 0; i < 1000; i++) {
    numbers += i; // 🚨 Creates 1,000 separate string objects on the heap!
}
```

* The Fix: If you need to build or modify strings aggressively inside a loop, always use the mutable StringBuilder class instead of a standard String.
