The java.io package provides Java’s foundational framework for reading and writing data. It operates primarily on the concept of Streams—ordered sequences of data moving from a source (input) to a destination (output).

To master Java I/O, you must understand its two distinct design pillars: Byte Streams (for raw binary data like images or compiled files) and Character Streams (for human-readable text), along with Decorators that add buffering or structural formatting to those streams.

Here is an architectural introduction to the 10 core classes of the java.io package.

------------------------------
## 1. Working with the File System: File
The File class is an abstract representation of file and directory pathnames. It does not read or write the contents of a file. Instead, it is used to check if a file exists, inspect file properties (like size or read/write permissions), create new empty directories, or delete items.

File file = new File("data.txt");if (file.exists()) {
    System.out.println("File size: " + file.length() + " bytes");
}

------------------------------
## 2. Byte Streams: Raw Binary Data
Byte streams process data 8 bits (1 byte) at a time. All byte stream classes inherit from InputStream or OutputStream.

* FileInputStream: Opens a direct pipeline to read raw bytes from a physical file.
* FileOutputStream: Opens a pipeline to write raw bytes to a physical file. If the file doesn't exist, it creates it.
* Best Used For: Copying images, audio, video, or any non-text binary file.

// Lower-level binary copy operationtry (FileInputStream in = new FileInputStream("input.jpg");
     FileOutputStream out = new FileOutputStream("output.jpg")) {
    int byteData;
    while ((byteData = in.read()) != -1) {
        out.write(byteData); // Processes raw binary information
    }
}

------------------------------
## 3. Character Streams: Text Data
Character streams process data 16-bit Unicode characters at a time, handling character encodings (like UTF-8) automatically under the hood. They inherit from Reader or Writer.

* FileReader: Connects to a text file to read characters.
* FileWriter: Connects to a text file to write characters.
* Best Used For: Reading or writing basic text files, CSVs, or markdown documents.

------------------------------
## 4. Buffered Streams: Speed and Efficiency
Directly reading or writing data to a disk byte-by-byte or character-by-character causes high overhead and hurts application performance. Buffered streams resolve this by introducing an internal memory buffer (typically 8KB). They act as wrappers around lower-level file streams to minimize disk interactions.

* BufferedReader: Wraps a Reader (like FileReader). It reads a large chunk of text from the disk into memory all at once and provides the highly useful .readLine() method to process text line-by-line.
* BufferedWriter: Wraps a Writer (like FileWriter). It writes text to an in-memory buffer and writes to the physical disk only when the buffer fills up or .flush() is explicitly invoked.

// Highly efficient, industry-standard text reading patterntry (BufferedReader reader = new BufferedReader(new FileReader("logs.txt"))) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line); // Processes text line by line from memory
    }
}

------------------------------
## 5. Formatting Output: PrintWriter
PrintWriter is a high-level character stream decorator that allows you to write formatted text configurations easily. It implements methods like print(), println(), and printf(), making it feel exactly like writing to System.out, but directing that output to a file instead. It never throws an IOException directly; developers must check for errors using checkError().

try (PrintWriter writer = new PrintWriter(new FileWriter("report.txt"))) {
    writer.println("--- Monthly Report ---");
    writer.printf("Total Revenue: $%.2f%n", 54300.50);
}

------------------------------
## 6. Object Streams: Serialization & Deserialization
These streams allow you to save entire Java objects directly to a file and reconstruct them later. For an object to pass through these streams, its class must implement the java.io.Serializable marker interface.

* ObjectOutputStream (Serialization): Converts the state of a live Java object into a sequence of binary bytes to be saved to a file or sent over a network.
* ObjectInputStream (Deserialization): Reads raw serialized bytes from a source file and reconstructs them into a live, active Java object in memory.

// Saving an object to disktry (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("user.ser"))) {
    UserAccount user = new UserAccount("admin", "securePass123");
    oos.writeObject(user); // Object structure is entirely preserved in binary format
}

------------------------------
## Summary Architecture Matrix

| Class | Type | Unit | Primary Purpose |
|---|---|---|---|
| File | Meta-data Utility | N/A | File properties, directory checks, deletions. |
| FileInputStream / FileOutputStream | Node Byte Stream | 8-bit Byte | Raw binary file reading/writing (images, audio). |
| FileReader / FileWriter | Node Character Stream | 16-bit Char | Basic text file reading/writing. |
| BufferedReader / BufferedWriter | Processing Filter | 16-bit Char | High-performance, buffered text manipulation. |
| PrintWriter | Processing Filter | 16-bit Char | Formatted human-readable output (printf, println). |
| ObjectInputStream / ObjectOutputStream | Processing Filter | Serialization | Converting live Java objects to/from byte streams. |
