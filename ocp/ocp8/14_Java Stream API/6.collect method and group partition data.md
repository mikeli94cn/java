In the Java Stream API, intermediate operations like .filter() and .map() transform the elements of a data pipeline, but they do not store the results []. To pull your data out of the stream and convert it back into a usable structure, you must execute a terminal operation using the .collect() method [].

The .collect() method acts as the pipeline's exit gateway, relying on utility strategies provided by the java.util.stream.Collectors class []. Beyond simply compiling items into a standard list, Collectors allows you to restructure your data completely by grouping or partitioning it into sophisticated dictionary maps [].

------------------------------
## 1. Saving Results to a Standard Collection
The most straightforward use of .collect() is compiling data elements back into a standard List, Set, or specific implementation structure [].

import java.util.List;import java.util.Set;import java.util.stream.Collectors;

List<String> rawNames = List.of("Alex", "Blake", "Alex", "Charlie");
// 1. Collect into a standard List (Preserves duplicates and insertion order)
List<String> listResult = rawNames.stream().collect(Collectors.toList()); // [Alex, Blake, Alex, Charlie]
// 2. Collect into a Set (Automatically strips out duplicate entries)
Set<String> setResult = rawNames.stream().collect(Collectors.toSet());   // [Alex, Blake, Charlie]

------------------------------
## 2. Grouping Data (Collectors.groupingBy)
The groupingBy() collector acts exactly like a SQL GROUP BY statement. It groups items based on a specific classification property and organizes them into a Map<Key, List<Value>> layout [].
You can group your data by any attribute, producing as many distinct classification buckets as your data demands.

import java.util.List;import java.util.Map;import java.util.stream.Collectors;
class Item {
    private String name;
    private String category;

    public Item(String name, String category) {
        this.name = name;
        this.category = category;
    }
    public String getCategory() { return category; }
    @Override
    public String toString() { return name; }
}
public class GroupingDemo {
    public static void main(String[] args) {
        List<Item> catalog = List.of(
            new Item("Laptop", "Electronics"),
            new Item("Desk", "Furniture"),
            new Item("Smartphone", "Electronics"),
            new Item("Chair", "Furniture")
        );

        // Grouping items dynamically by their category string field
        Map<String, List<Item>> inventoryByCategory = catalog.stream()
            .collect(Collectors.groupingBy(Item::getCategory));

        System.out.println("Grouped Catalog: " + inventoryByCategory);
        // Outputs: Grouped Catalog: {Electronics=[Laptop, Smartphone], Furniture=[Desk, Chair]}
    }
}

## 3. Partitioning Data (Collectors.partitioningBy)
partitioningBy() is a specialized, high-speed variation of grouping. Instead of accepting a general classification property, it consumes a Lambda Predicate expression (a true/false validation test) [].
Because a predicate can only evaluate to true or false, partitioning always splits your data collection into exactly two distinct blocks organized into a Map<Boolean, List<Value>>.

* Key true: Holds a list of elements that successfully passed the validation test [].
* Key false: Holds a list of elements that failed the validation test [].

import java.util.List;import java.util.Map;import java.util.stream.Collectors;
public class PartitioningDemo {
    public static void main(String[] args) {
        List<Integer> finalGrades = List.of(55, 82, 45, 90, 73);

        // Partitioning grades into Passing (>= 60) vs. Failing (< 60)
        Map<Boolean, List<Integer>> gradeReport = finalGrades.stream()
            .collect(Collectors.partitioningBy(grade -> grade >= 60));

        System.out.println("Passing list (true):  " + gradeReport.get(true));  // [82, 90, 73]
        System.out.println("Failing list (false): " + gradeReport.get(false)); // [55, 45]
    }
}

## Summary Restructuring Choice Matrix

| Collector Method | Output Map Key Type | Number of Resulting Buckets | Primary Use Case Goal |
|---|---|---|---|
| Collectors.toList() | (None: standard List) | 1 sequential list [] | General read/write data output preservation. |
| Collectors.groupingBy() | Dynamic (e.g., String, Enum) | Infinitely many (1 bucket per matching value) | Categorizing objects into multi-tiered classifications. |
| Collectors.partitioningBy() | Strict Boolean (true/false) | Exactly 2 structural buckets | Binary segregation checks (Pass/Fail, Active/Inactive). |
