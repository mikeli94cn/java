In Java, an object’s lifecycle describes its entire journey inside your computer's memory—from the exact moment it is brought into existence to the moment it is destroyed and its memory is reclaimed.

Because Java manages memory automatically, understanding this lifecycle helps you write efficient, crash-free applications.


## The Three Phases of an Object's Lifecycle
```text
 [ PHASE 1: Creation ] --------> Object is allocated on the Heap using 'new'
          |
          v
 [ PHASE 2: Dereference ] -----> References are cut or shifted (e.g., Reassignment)
          |
          v
 [ PHASE 3: Garbage Collection ] -> JVM frees up the memory automatically
```

### Phase 1: Creation (Birth)
An object is born when you use the new keyword followed by a class constructor.
When this line executes, two things happen simultaneously in your computer's memory:

   1. On the Heap: Java allocates a chunk of dynamic memory to store the object's actual data and fields.
   2. On the Stack: Java creates a reference variable (the "remote control") holding the memory address of that heap object.
```java
// A new Car object is born on the heap; 'myCar' points to it.
Car myCar = new Car("Red"); 
```

### Phase 2: Dereference by Reassignment (Life)
An object stays alive as long as there is at least one active reference variable pointing to it. However, if an object loses all its references, it becomes "unreachable."
One common way an object loses its reference is through reassignment—meaning you point the reference variable to a completely different object or to null.
```java
Car myCar = new Car("Red");   // Object A is created
myCar = new Car("Blue");      // Object B is created. 'myCar' now points to Object B!
```
### What happened to Object A (the Red Car)?
Because myCar was overwritten, Object A is now dereferenced. It is still floating around on the heap, but it has no remote controls pointing to it anymore. The program can never access it or use it again.
Other ways an object can become dereferenced include:

* Going out of scope: A local variable created inside a method is destroyed when the method finishes executing.
* Explicitly nullifying: Explicitly setting the pointer to nothing (myCar = null;).


### Phase 3: Garbage Collection (Death)
Once an object is completely dereferenced and unreachable, it becomes eligible for Garbage Collection (GC).
Java features an automatic background daemon called the Garbage Collector. Instead of requiring developers to manually delete objects from memory (like in C or C++), the JVM handles it:

   1. The Garbage Collector runs periodically in the background.
   2. It scans the heap looking for objects with zero active references.
   3. It deletes those unreachable objects and frees up that memory space so the computer can reuse it for future objects.

⚠️ Crucial Note: An object is not destroyed the exact millisecond it loses its reference. It is simply marked as "eligible" for destruction. The Garbage Collector will destroy it whenever it determines the system needs to clean up memory.


## Code Walkthrough Example
```java
public class LifecycleDemo {
    public static void main(String[] args) {
        // 1. Creation: Object A (Dog 1) is born
        Dog dog1 = new Dog("Buddy"); 
        
        // 2. Creation: Object B (Dog 2) is born
        Dog dog2 = new Dog("Max");   
        
        // 3. Reassignment: dog1 drops Buddy and now points to Max (Object B).
        // Object A (Buddy) is now completely dereferenced!
        dog1 = dog2; 
        
        // 4. Object A (Buddy) is now eligible for Garbage Collection.
        // At some point in the future, the JVM will reclaim Buddy's memory.
    }
}
```
