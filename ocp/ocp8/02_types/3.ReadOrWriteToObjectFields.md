In Java, reading or writing to object fields (also known as instance variables or attributes) is how you interact with the state of an object. To do this, Java relies heavily on a special operator called the dot operator (.), as well as the concept of Encapsulation.

Here is how you manipulate an object's fields depending on how the class is designed.


## 1. Direct Access (Using the Dot Operator)
If an object's fields are marked as public, you can read or write to them directly from anywhere in your program by using the variable name, followed by a dot, followed by the field name.
### The Syntax:

* Writing (Assigning a value): objectName.fieldName = value;
* Reading (Retrieving a value): System.out.println(objectName.fieldName);
```java
class Player {
    public String username; // public field
    public int score;       // public field
}
public class Main {
    public static void main(String[] args) {
        Player player1 = new Player();

        // WRITING to fields directly
        player1.username = "PixelKnight";
        player1.score = 450;

        // READING from fields directly
        System.out.println(player1.username + " has a score of " + player1.score);
    }
}
```

## 2. Controlled Access (Using Getters and Setters)
In real-world Java development, directly exposing fields as public is discouraged because it breaks the rule of Encapsulation. If anyone can modify a field directly, they could accidentally input invalid data (e.g., setting a product's price to a negative number).

Instead, fields are typically marked private, meaning they cannot be accessed directly with a dot operator outside the class. To read or write to them, you must use public methods called Getters and Setters:

* Getter (To Read): A method that returns the value of the private field.
* Setter (To Write): A method that takes a parameter and assigns it to the private field, often validating the data first.
```java
class BankAccount {
    private double balance; // private field: protected from direct access

    // SETTER (Writing with validation)
    public void setBalance(double amount) {
        if (amount >= 0) {
            this.balance = amount; // 'this' refers to the current object's field
        } else {
            System.out.println("Error: Balance cannot be negative!");
        }
    }

    // GETTER (Reading)
    public double getBalance() {
        return this.balance;
    }
}
```
## How to read and write using these methods:
```java
public class Main {
    public static void main(String[] args) {
        BankAccount account = new BankAccount();

        // WRITING via the setter
        account.setBalance(500.00); 
        account.setBalance(-20.00); // Triggers the validation error!

        // READING via the getter
        System.out.println("Current Balance: $" + account.getBalance());
    }
}
```

## Summary Direct Comparison

| Access Type | Code Example | When to Use | Risk Level |
|---|---|---|---|
| Direct (Dot Operator) | obj.age = 21; | Quick scripts, temporary local tracking classes. | High (No validation check, data can be corrupted easily). |
| Indirect (Getters/Setters) | obj.setAge(21); | Standard practice for professional software design. | Low (Allows complete control over who reads or writes data). |
