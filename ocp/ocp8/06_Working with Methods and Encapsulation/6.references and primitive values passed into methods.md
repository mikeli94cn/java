In Java, understanding how data is passed into a method is one of the most critical concepts for avoiding subtle bugs. The golden rule of Java memory behavior is simple: Java is strictly "Pass-by-Value."
This means that whenever you pass a variable into a method, Java always creates a brand-new copy of whatever is inside that variable's container and hands that copy to the method.
However, because primitive variables and object reference variables store completely different things, "Pass-by-Value" creates two completely opposite effects when values are changed inside a method.

------------------------------
## 1. Passing Primitive Values (No Effect)
A primitive variable (like int, double, boolean) stores the actual raw value directly on the Stack.
When you pass a primitive into a method, Java makes a copy of that raw number. The method manipulates the copy inside its own local scope. The original variable outside the method remains completely unchanged.

public class PrimitiveTest {
    public static void main(String[] args) {
        int score = 10;
        modifyPrimitive(score);
        
        System.out.println("Original Score: " + score); // Outputs: 10 (Unchanged!)
    }

    public static void modifyPrimitive(int localScore) {
        localScore = 999; // Changes ONLY the local copy
    }
}

------------------------------
## 2. Passing Object References (Two Distinct Effects)
An object reference variable (like a String, Array, or custom class object) does not store the actual object data; it stores a memory address (pointer) to where the object sits on the Heap.
When you pass an object reference into a method, Java copies that memory address. Now, both the original variable and the method's parameter are holding copies of the same address—meaning both point to the exact same object on the heap.
This sets up two different scenarios depending on how the method acts:
## Scenario A: Modifying the object's fields (Changes the original object)
If the method uses the address to modify a field inside the object, the original object is permanently altered, because both variables point to that same single object.

class Player { int health = 100; }
public class ObjectTest {
    public static void main(String[] args) {
        Player p1 = new Player();
        damagePlayer(p1);
        
        System.out.println("Player Health: " + p1.health); // Outputs: 50 (Altered!)
    }

    public static void damagePlayer(Player localPlayer) {
        localPlayer.health = 50; // Follows the address and changes the heap data
    }
}

## Scenario B: Reassigning the reference variable (No effect on original object)
If the method attempts to reassign the parameter to a new object using the assignment operator (=), it simply breaks that local connection. The local parameter now points to a brand-new memory address, leaving the original object completely untouched.

public class ReassignTest {
    public static void main(String[] args) {
        Player p1 = new Player(); // Points to Object A (health 100)
        replacePlayer(p1);
        
        System.out.println("Player Health: " + p1.health); // Outputs: 100 (Unchanged!)
    }

    public static void replacePlayer(Player localPlayer) {
        localPlayer = new Player(); // Points localPlayer to a brand-new Object B
        localPlayer.health = 0;     // Modifies Object B, not Object A
    }
}

------------------------------
## Summary Behavior Matrix

| Variable Type | What is Passed? | Modifying via Parameter Affects Original? | Reassigning Parameter Affects Original? |
|---|---|---|---|
| Primitives (int, char, etc.) | A copy of the raw value. | No. | No. |
| Object References (Arrays, Custom Classes) | A copy of the memory address. | Yes. (Altering fields changes the shared object). | No. (Reassignment breaks the local address copy link). |
