In Java, access modifiers are keywords used to set the visibility and accessibility of classes, constructors, fields, and methods. They are the primary tools used to enforce Encapsulation (data hiding), allowing you to control which parts of your application can look at or modify your code.

------------------------------
## The 4 Access Levels in Java
Java provides four levels of access. Three use explicit keywords, while one (Package-Private) is the default when no keyword is specified.
Arranged from most accessible to most restrictive:
## 1. public (Universal Access)
Any component marked public is visible to every class across your entire Java application, regardless of what package it lives in.

public class DiagnosticTool {
    public void runCheck() {
        System.out.println("Accessible everywhere.");
    }
}

## 2. protected (Package + Inheritance Access)
Components marked protected are accessible to:

* All classes living within the same package.
* Subclasses (child classes) located in different packages via inheritance.

public class Asset {
    protected double value; // Child classes in other packages can see this field
}

## 3. Default / Package-Private (Package-Only Access)
If you do not type an access modifier keyword, Java automatically assigns the default level, known as package-private. The component is strictly visible only to classes inside the same package folder. It is completely hidden from external packages.

class InternalHelper { // No modifier keyword means package-private
    void formatData() { // Package-private method
        System.out.println("Only visible within my own package folder.");
    }
}

## 4. private (Class-Only Access)
The most restrictive modifier. A private component is visible only within the specific class where it is declared. No outside classes—not even subclasses or classes in the same package—can access it. This is the cornerstone of protecting an object's internal state.

public class UserAccount {
    private String password; // Completely hidden from the outside world

    private void encryptPassword() {
        // Internal class logic only
    }
}

------------------------------
## Summary Access Level Matrix

| Modifier Keyword | Visible to Same Class? | Visible to Same Package? | Visible to Subclasses (Any Package)? | Visible to Global World? |
|---|---|---|---|---|
| public | Yes | Yes | Yes | Yes |
| protected | Yes | Yes | Yes | No |
| (default) | Yes | Yes | No | No |
| private | Yes | No | No | No |

------------------------------
## Best Practices for Applying Modifiers

   1. Default to Restrictive: Start by making all your class fields private. Only open them up to broader access (via public getters/setters or protected status) if your application architecture strictly demands it.
   2. Top-Level Class Restrictions: Top-level classes (classes written directly in a .java file) can only be marked public or default (package-private). They cannot be marked private or protected.
   3. Interface Methods: By default, all methods declared inside a standard Java interface are automatically implicitly public.
