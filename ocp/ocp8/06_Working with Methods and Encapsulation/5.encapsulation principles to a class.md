In object-oriented programming, Encapsulation is the practice of bundling an object's data (fields) and behaviors (methods) together into a single unit (a class) while hiding the internal implementation details from the outside world. It is often referred to as "data hiding."
Think of a pill capsule: the active ingredients are sealed safely inside, and you can only interact with the smooth outer shell. Encapsulation prevents external code from directly tampering with an object's internal state, ensuring data integrity and security.

------------------------------
## The Three Steps to Enforce Encapsulation
To implement encapsulation in a Java class, you follow a strict design pattern:

1. Mark all fields as PRIVATE --------> Prevents direct external access/tampering
2. Create public GETTER methods ------> Provides safe, read-only access to the data
3. Create public SETTER methods ------> Provides controlled, validated write access

------------------------------
## Code Comparison: Non-Encapsulated vs. Encapsulated## The Bad Way (No Encapsulation)
When fields are public, anyone can change them to invalid, nonsensical, or malicious values, causing the application to crash later.

class BankAccount {
    public double balance; // 🚨 DANGEROUS! Anyone can modify this directly
}
public class Main {
    public static void main(String[] args) {
        BankAccount account = new BankAccount();
        account.balance = -50000.00; // Bug: A bank balance shouldn't be negative!
    }
}

## The Right Way (Proper Encapsulation)
By hiding the fields and routing changes through public methods, we can filter, inspect, and reject bad data before it ruins our object's state.

public class BankAccount {
    // 1. Private fields protect the internal state
    private double balance; 

    // 2. Getter method provides safe read access
    public double getBalance() {
        return this.balance;
    }

    // 3. Setter method enforces business logic and validation rules
    public void deposit(double amount) {
        if (amount > 0) {
            this.balance += amount; 
            System.out.println("Deposited: $" + amount);
        } else {
            System.out.println("Error: Deposit amount must be positive!");
        }
    }
}

------------------------------
## Core Benefits of Encapsulation

* Control & Validation: You control exactly how a variable is updated. For example, a setAge(int age) method can throw an error if someone passes a negative number.
* Flexibility & Maintainability: If you decide to change how a field is stored (e.g., changing a birthday field from a String to a LocalDate object), you only have to change the code inside the class. Any external code calling getBirthday() stays completely untouched.
* Read-Only or Write-Only Fields: By omitting a setter method entirely, you make a field read-only to the rest of the application.
