In Java, methods are reusable blocks of code that perform a specific task. They prevent code duplication by allowing you to write logic once and execute it anywhere in your program. To make methods flexible and dynamic, you can pass data into them using arguments and receive results back using return values.


## 1. The Anatomy of a Method
Every Java method requires a specific signature structure. Here is a standard method that calculates the total cost of an item including tax:
```java
public double calculateTotal(double price, double taxRate) {
    double total = price + (price * taxRate);
    return total; 
}
```
### Breakdown of Components:

* public (Access Modifier): Determines who can call this method.
* double (Return Type): The exact data type of the result this method sends back. If a method performs an action but returns nothing, this keyword must be void.
* calculateTotal (Method Name): Written in camelCase, indicating what the method does.
* double price, double taxRate (Parameters): The variables defined in the method declaration that act as blueprints for incoming data.
* return total;: The keyword that stops execution and pushes the final value back to wherever the method was called.

### Calling the Method (Passing Arguments):
When you invoke the method, you pass in the actual values, which are called arguments:
```java
// Invoking the method and capturing the return value in a variable
double finalInvoice = calculateTotal(19.99, 0.08); 
System.out.println("Total: $" + finalInvoice);
```

## 2. Method Overloading (Compile-Time Polymorphism)
Method overloading is a powerful feature that allows a class to have multiple methods with the exact same name, as long as their parameter lists are different.

Java figures out which method to run based on the types or number of arguments you pass into it. This keeps your API clean so you don't have to name things addInt(), addDouble(), or addThreeNumbers().
### Rules for Overloading:
Methods can be overloaded by changing:

   1. The number of parameters.
   2. The data types of the parameters.
   3. The order of the parameter types.


* Note: Changing only the return type does not count as overloading and will result in a compiler error.

### Code Example: Overloading a printReceipt Method
```java
public class ReceiptManager {

    // Method 1: Accepts a double
    public void printReceipt(double total) {
        System.out.println("Receipt Total: $" + total);
    }

    // Method 2: Overloaded by changing the parameter type to a String
    public void printReceipt(String orderId) {
        System.out.println("Receipt for Order ID: " + orderId);
    }

    // Method 3: Overloaded by changing the number of parameters
    public void printReceipt(double total, String customerName) {
        System.out.println("Customer: " + customerName + " | Total: $" + total);
    }
}
```
### How Java Automatically Routes the Call:
```java
ReceiptManager manager = new ReceiptManager();

manager.printReceipt("ORD9923");         // Calls Method 2
manager.printReceipt(45.50);             // Calls Method 1
manager.printReceipt(120.00, "Sarah");   // Calls Method 3
```

## Summary Rules Table

| Concept | Definition | Rule to Remember |
|---|---|---|
| Parameters | The variable placeholders in the method header. | Must specify a explicit data type for each parameter. |
| Arguments | The actual values passed during execution. | Must match the parameter types in the exact order declared. |
| Return Value | The final output sent back by the method. | Must match the stated return type (or use void for none). |
| Overloading | Multiple methods sharing the same name. | Must have unique parameter counts or data types. |
