In Java, abstract classes and interfaces are the two primary tools used to achieve Abstraction (complexity hiding) and define architectural templates for your code. They allow you to define what an application component should do without dictating how it must do it.
While they share a similar purpose, they serve completely different design goals: abstract classes model a strict inheritance identity, whereas interfaces model a flexible capability or contract.

------------------------------
## 1. Abstract Classes (The Shared Core)
An abstract class is a class marked with the abstract keyword. It serves as a partial blueprint. It cannot be instantiated directly using the new keyword; it can only be extended by concrete child subclasses.

* 
* Abstract Methods: Methods declared without an implementation body (no curly braces { }). Any concrete subclass must override and implement these methods.
* Concrete Components: Unlike interfaces, an abstract class can contain regular methods with full code bodies, constructor chains, and instance variables (fields) that track object states.
* 

## Code Example:

// Abstract Parent: Defines an identity (An item in an ecosystem)public abstract class Employee {
    private String name; // Can hold instance data fields

    public Employee(String name) { this.name = name; }
    public String getName() { return name; } // Concrete method inherited as-is

    // Abstract method: Every employee gets paid, but calculations differ
    public abstract double calculateSalary(); 
}
class SalariedEmployee extends Employee {
    private double fixedSalary;

    public SalariedEmployee(String name, double fixedSalary) {
        super(name);
        this.fixedSalary = fixedSalary;
    }

    @Override
    public double calculateSalary() { return fixedSalary; } // Implementation required
}

------------------------------
## 2. Interfaces (The Shared Contract)
An interface is a completely abstract structure that establishes a strict contractual agreement. It defines a set of behaviors that any class can choose to implement, regardless of where that class sits in the inheritance tree.

* 
* Multiple Implementation: A Java class can only extend one parent class, but it can implement multiple interfaces simultaneously (e.g., class Car implements Drivable, Insurable).
* Implicit Rules: By default, all variables in an interface are automatically public static final (constants), and all standard methods are automatically abstract.
* Modern Additions: Interfaces can now include code logic via default methods or static methods.
* 

## Code Example:

// Interface: Defines a capability/action contractpublic interface Encryptable {
    String encryptData(String rawText); // Implicitly public abstract
}
// Completely unrelated classes can implement the same contractpublic class UserMessage implements Encryptable {
    @Override
    public String encryptData(String rawText) { return "MSG-ROT13:" + rawText; }
}
public class DatabaseLog implements Encryptable {
    @Override
    public String encryptData(String rawText) { return "DB-AES:" + rawText; }
}

------------------------------
## Direct Comparison: Architecture & Rules
The choice between these two tools comes down to fundamental relationship design: Inheritance Hierarchy ("Is-A") vs. Functional Behavior ("Can-Do").

| Structural Feature | Abstract Class | Interface |
|---|---|---|
| Relationship Intent | Is-A: Establishes a fundamental, core identity identity (e.g., a Dog is an Animal). | Can-Do / Acts-As: Attaches a specialized capability (e.g., a Dog can be Runnable). |
| Inheritance Capacity | A subclass can only extend one abstract class. | A class can implement infinitely many interfaces. |
| Instance Variables | Can have full instance fields (private int health;) to track unique object state. | Cannot track instance state. All fields are permanent global constants (public static final). |
| Constructors | Can have constructors to initialize parent state for subclasses. | Cannot have constructors (cannot handle initialization). |
| Key Keyword | Inherited using extends. | Linked using implements. |
