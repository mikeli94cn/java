In object-oriented programming, Inheritance is a foundational mechanism that allows a new class to adopt (or inherit) the attributes (fields) and behaviors (methods) of an existing class.

The existing class is known as the Parent class (or Superclass), and the new class is known as the Child class (or Subclass). Think of it like family genealogy: a child automatically inherits physical traits from their parents, but they can still develop unique skills or traits of their own.

In Java, inheritance is explicitly triggered using the extends keyword.


## 1. Visualizing Inheritance in Code
Imagine designing software for a car dealership. Instead of writing separate, redundant classes from scratch for every type of vehicle, you establish a hierarchy:
```java
// The Superclass (Parent)
public class Vehicle {
    public String brand;
    public int year;

    public void honk() {
        System.out.println("Beep beep!");
    }
}
// The Subclass (Child) inheriting from Vehicle
public class Car extends Vehicle {
    // Car automatically has brand, year, and honk()!
    public int numberOfDoors; // Custom attribute unique only to Cars
}
```
### Instantiating and Using the Child Class:
```java
public class Main {
    public static void main(String[] args) {
        Car myCar = new Car();
        
        // Accessing inherited fields and methods directly
        myCar.brand = "Toyota"; 
        myCar.honk(); // Outputs: Beep beep!
        
        // Accessing custom child fields
        myCar.numberOfDoors = 4;
    }
}
```

## 2. Core Benefits of Inheritance
Implementing an inheritance hierarchy provides four major structural advantages:

* ✅ Code Reusability: You write common logic once in the parent class. Every subclass automatically gains access to it, saving hundreds of lines of identical code across your codebase.
* 📈 Extensibility & Specialization: Child classes can effortlessly add custom features (like unique fields or methods) to build specific functionality on top of a solid baseline without breaking the general system layout.
* 🛠️ Centralized Maintenance: If a shared behavior contains a bug or requires an update, you only have to modify it in one location—the parent class. Every child class instantly receives the correction.
* 🔄 Enables Polymorphism: It establishes an "Is-A" relationship (e.g., a Car is a Vehicle). This allows you to write flexible methods that can accept any type of vehicle and treat them dynamically at runtime.


## 3. Rules and Restrictions to Know in Java
While inheritance is incredibly powerful, Java enforces a few strict architectural guardrails:

   1. Single Inheritance Only: A child class can only extend one single parent class. Java explicitly bans multiple inheritance (e.g., class Car extends Vehicle, Machine is illegal) to prevent naming conflicts and ambiguity.
   2. The Private Trap: A child class inherits everything, but it cannot directly access private fields or methods of the parent class. To read or write to private parent fields, the child must route its requests through public or protected getters and setters.
   3. The final Keyword: If a class is marked as final (e.g., public final class String), it is sealed—meaning no class is allowed to inherit from it.
