In modern Java architectures, managing manual thread creation (new Thread()) is highly discouraged for enterprise applications. It introduces massive overhead and leaves systems vulnerable to resource exhaustion. Instead, Java utilizes the Concurrency Utilities (java.util.concurrent) framework. This model separates the task definition (what the work is) from the execution mechanism (how the work runs) using an abstraction called a Thread Pool.

Here is an architectural introduction to structuring concurrent tasks using Runnable, Callable, and ExecutorService.

------------------------------
## 1. Task Definitions: Runnable vs. Callable
To execute a job concurrently, you must first encapsulate your logic inside one of two functional interfaces:
## Runnable (Fire-and-Forget)
A task that executes logic but does not return a value and cannot throw checked exceptions. It features a single public void run() method.
## Callable (Task with a Result)
A modern alternative introduced in Java 5. A Callable<V> returns a computed result of type V and is permitted to throw checked exceptions. It features a single public V call() method.

// A Runnable task definition (No return value)
Runnable runnableTask = () -> {
    System.out.println("Processing async telemetry data...");
};
// A Callable task definition (Returns a String, handles checked exceptions)
Callable<String> callableTask = () -> {
    // Simulating a network fetch that might fail
    Thread.sleep(500); 
    return "Data fetched successfully!";
};

------------------------------
## 2. The Execution Engine: ExecutorService
An ExecutorService represents a managed pool of worker threads. Instead of spawning an entirely new system thread for every task, you submit tasks to the ExecutorService. The service queues the tasks and assigns them to available worker threads automatically, recycling threads when jobs finish.
You create these pools using utility factory methods found in the Executors class:

* 
* Executors.newFixedThreadPool(int): Creates a pool with a set number of permanent threads.
* Executors.newCachedThreadPool(): Creates a dynamic pool that spawns new threads as needed and cleans them up when idle.
* 

## Code Example: Executing Tasks via Thread Pools

import java.util.concurrent.Callable;import java.util.concurrent.ExecutorService;import java.util.concurrent.Executors;import java.util.concurrent.Future;
public class ConcurrencyExample {
    public static void main(String[] args) throws Exception {
        // 1. Instantiate an ExecutorService with a pool of 3 worker threads
        ExecutorService executor = Executors.newFixedThreadPool(3);

        // 2. Submit a Runnable task (Fire-and-forget)
        executor.execute(() -> System.out.println("Runnable task running asynchronously."));

        // 3. Submit a Callable task
        Callable<Integer> calculationTask = () -> {
            int total = 0;
            for (int i = 1; i <= 100; i++) total += i;
            return total;
        };
        
        // Submitting returns a Future token immediately
        Future<Integer> futureResult = executor.submit(calculationTask);

        // 4. Retrieve the result (This call blocks until the thread finishes computing)
        Integer answer = futureResult.get();
        System.out.println("Calculation Result from worker thread: " + answer);

        // 5. CRITICAL: Always shut down the executor to release system hooks
        executor.shutdown();
    }
}

------------------------------
## 3. Asynchronous Coordination: The Future Interface
When you submit a Callable task to an ExecutorService, the pool immediately hands you back a Future object. A Future acts as a placeholder or ticket for a calculation that hasn't finished yet.

* 
* future.isDone(): Checks if the worker thread has completed the task without halting execution.
* future.get(): Blocks your current main thread and waits for the worker thread to finish, then safely extracts the computed value.
* 

------------------------------
## Comparison: Runnable vs. Callable

| Feature | Runnable | Callable<V> |
|---|---|---|
| Method Signature | public void run() | public V call() throws Exception |
| Return Value | None (void) | Generics-driven value (V) |
| Exception Handling | Limited to internal try-catch blocks. | Can throw any checked/unchecked exception upward. |
| Execution Trigger | Compatible with new Thread(r).start() or ExecutorService. | Executed exclusively through an ExecutorService. |
| Result Tracking | Hard to track without shared, thread-unsafe state variables. | Tracked elegantly using a returned Future<V> reference. |
