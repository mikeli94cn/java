In the Java Stream API, sorting a collection is handled by the .sorted() method, which is a powerful intermediate operation [].

The single most critical architectural advantage of using the Stream API for sorting is that it leaves your original data source completely untouched and unmodified []. Instead of overwriting the initial array or ArrayList, it streams the elements out, organizes them midway down the pipeline, and outputs a brand-new, sorted collection [].

------------------------------
## 1. The Two Flavors of the .sorted() Method
Java provides two ways to invoke a sort operation depending on what type of data you are processing:
## Option A: .sorted() (Natural Order Sorting)
Takes zero arguments. It relies on the data types themselves having a built-in default sorting order []. This works out of the box for core Java types like String (alphabetical), numbers (ascending), and modern dates [].

List<String> codes = List.of("Gamma", "Alpha", "Beta");

List<String> sortedCodes = codes.stream()
    .sorted() // Uses natural alphabetical sorting automatically []
    .toList(); // Compiles results into a new List []// Result: ["Alpha", "Beta", "Gamma"]

## Option B: .sorted(Comparator) (Custom Order Sorting)
Takes a custom Comparator lambda expression or a method reference []. You use this when sorting custom objects (like a User or Product class) where you must explicitly tell Java which variable or field to sort by [].
------------------------------
## 2. Code Blueprint: Advanced Custom Object Sorting
Imagine sorting a list of corporate Employee profiles. We can use the built-in factory method Comparator.comparing() to cleanly map out complex sorting pipelines, such as organizing users by salary, or reversing the order to sort from highest-paid to lowest-paid.

import java.util.Comparator;import java.util.List;
class Employee {
    private String name;
    private double salary;

    public Employee(String name, double salary) {
        this.name = name;
        this.salary = salary;
    }
    public String getName() { return name; }
    public double getSalary() { return salary; }
    @Override
    public String toString() { return name + " ($" + salary + ")"; }
}
public class StreamSortDemo {
    public static void main(String[] args) {
        List<Employee> team = List.of(
            new Employee("Alice", 75000.00),
            new Employee("Bob", 120000.00),
            new Employee("Charlie", 95000.00)
        );

        // --- PIPELINE 1: Sorting Ascending by Salary ---
        List<Employee> lowToHigh = team.stream()
            .sorted(Comparator.comparing(Employee::getSalary)) // Method reference comparator []
            .toList(); []
        System.out.println("Salary (Low to High):  " + lowToHigh);


        // --- PIPELINE 2: Sorting Descending (High to Low) by Salary ---
        List<Employee> highToLow = team.stream()
            .sorted(Comparator.comparing(Employee::getSalary).reversed()) // Chain .reversed() []
            .toList(); []
        System.out.println("Salary (High to Low):  " + highToLow);
    }
}

## The Execution Output:

Salary (Low to High):  [Alice ($75000.0), Charlie ($95000.0), Bob ($120000.0)]
Salary (High to Low):  [Bob ($120000.0), Charlie ($95000.0), Alice ($75000.0)]

## 3. Critical Performance Warning: Stateful & Blocking
While operations like .filter() process elements one by one on an on-demand assembly line, .sorted() is classified as a stateful, blocking intermediate operation [].
This means that a stream cannot start passing elements further down the pipeline until 100% of the data elements have arrived at the sorting station []. If you try to sort an infinite or massively large dataset, your application can run out of memory or pause significantly []. For maximum performance, always place your .filter() operations before your .sorted() statement to trim down the collection size first.
