In Java, an exception is an unexpected event that disrupts the normal execution of your code. If left unhandled, an exception causes the program to crash instantly.

A try-catch block acts as an application safety net. It allows you to intercept these disruptions, handle them gracefully, and keep your application running.


## 1. The Structure of a try-catch Block
The structure is split into two distinct zones:

* The try Block: You place the risky code that might throw an exception inside these braces.
* The catch Block: If an exception occurs inside the try block, Java immediately jumps here to execute your backup/recovery logic.
```java
try {
    // Risky code goes here
} catch (SpecificExceptionType e) {
    // Recovery or error logging logic goes here
}
```

## 2. How Exceptions Alter Normal Program Flow
To understand the mechanics, let’s trace a script that attempts to divide a number by zero.
## Scenario A: The Exception is Handled (Graceful Recovery)
When an exception triggers, Java immediately aborts the remaining lines inside the try block and teleports straight to the matching catch block. Once the catch block finishes, the program resumes normal execution on the lines below the entire block.
```java
public class FlowDemo {
    public static void main(String[] args) {
        System.out.println("Step 1: Application starts.");

        try {
            System.out.println("Step 2: Attempting division...");
            int result = 10 / 0; // ⚡ An ArithmeticException happens HERE!
            
            System.out.println("Step 3: This line will NEVER run.");
        } catch (ArithmeticException e) {
            System.out.println("Step 4: Caught division by zero! Handling error...");
        }

        System.out.println("Step 5: Application continues running normally!");
    }
}
```
### The Output Timeline:
```
Step 1: Application starts.
Step 2: Attempting division...
Step 4: Caught division by zero! Handling error...
Step 5: Application continues running normally!
```

* Notice: Step 3 was completely skipped, but the program safely completed Step 5 without crashing.

### Scenario B: The Exception is Unhandled (Sudden Crash)
If you omit the try-catch block (or if the exception thrown doesn't match the type specified in your catch block), Java halts execution entirely, prints a stack trace to the console, and kills the application process immediately.

## 3. Handling Multiple Exceptions
A single piece of code might be capable of failing in multiple ways. You can stack multiple catch blocks underneath a single try block to handle different errors uniquely.

* The Rule of Order: Java evaluates catch blocks from top to bottom. You must always place specific subclasses first and broader parent classes (like general Exception) last. Otherwise, the general parent will swallow all errors, causing a compiler error.
```java
try {
    int[] numbers = {5, 10};
    int divisor = numbers[2]; // ⚡ Throws ArrayIndexOutOfBoundsException
    int result = 50 / divisor;
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Error: That array index doesn't exist!");
} catch (ArithmeticException e) {
    System.out.println("Error: Cannot divide by zero!");
} catch (Exception e) {
    System.out.println("Error: A generic problem occurred.");
}
```

## Summary Flow Checklist

| Location of Error | Does the rest of the try block run? | Does the catch block run? | Does code after the try-catch run? |
|---|---|---|---|
| No Error occurs | Yes (Completely) | No | Yes |
| Error occurs & is Caught | No (Aborts instantly) | Yes | Yes (Normal recovery) |
| Error occurs & NOT Caught | No (Aborts instantly) | No | No (Application crashes) |
