In advanced Java class design, controlling how your objects manage their internal states and how they are instantiated is critical for building predictable, thread-safe software. Two of the most important design patterns used to achieve this control are Singleton Classes and Immutable Classes.

------------------------------
## 1. Singleton Classes (Enforcing a Single Instance)
A Singleton class is a design pattern that ensures a class has exactly one single instance in memory across the entire lifecycle of the application, while providing a global point of access to it.

* Common Use Cases: Centralized loggers, database connection pools, thread pools, or configuration managers where creating multiple objects would waste memory or cause synchronization conflicts.

## How to Implement a Singleton:
To restrict an object from being duplicated, you must block standard access and provide a controlled gateway:

   1. Make the constructor private so no external code can type new MyClass().
   2. Create a private static field inside the class to hold the single, unique instance.
   3. Provide a public static method (typically named getInstance()) that returns that single instance.

public class DatabaseConnectionPool {
    // Step 1: Create the single instance in memory
    private static DatabaseConnectionPool instance = new DatabaseConnectionPool();

    // Step 2: Make the constructor private to block external instantiation
    private DatabaseConnectionPool() {
        System.out.println("Database pool initialized.");
    }

    // Step 3: Provide a public static gateway to get the instance
    public static DatabaseConnectionPool getInstance() {
        return instance;
    }

    public void executeQuery(String sql) {
        System.out.println("Executing: " + sql);
    }
}

## Using the Singleton:

public class Main {
    public static void main(String[] args) {
        // DatabaseConnectionPool pool = new DatabaseConnectionPool(); // ❌ COMPILER ERROR!

        // Accessing the shared instance cleanly
        DatabaseConnectionPool pool1 = DatabaseConnectionPool.getInstance();
        DatabaseConnectionPool pool2 = DatabaseConnectionPool.getInstance();

        System.out.println(pool1 == pool2); // Outputs: true (They point to the EXACT same object)
    }
}

## 2. Immutable Classes (Enforcing Unmodifiable Objects)
An Immutable class is designed so that once an object is created on the heap, its data and state can never be changed. The most famous built-in example of this pattern is the String class [].

* Core Advantage: Immutable objects are inherently thread-safe. Multiple threads can read from them simultaneously without any risk of data corruption, completely eliminating the need for complex locking or synchronization mechanisms.

## How to Implement an Immutable Class:

   1. Mark the class as final so it cannot be inherited or extended (which would allow child classes to add mutable fields).
   2. Mark all instance variables as private and final. This guarantees they must be assigned once in the constructor and can never be overwritten later.
   3. Do not provide any setter methods.
   4. Initialize all fields via a constructor.

// Step 1: Prevent inheritance using 'final'public final class ImmutableUser {
    // Step 2: Make all fields private and final
    private final int id;
    private final String username;

    // Step 3: Initialize everything inside the constructor
    public ImmutableUser(int id, String username) {
        this.id = id;
        this.username = username;
    }

    // Step 4: Provide getters, but absolutely NO setters
    public int getId() { return id; }
    public String getUsername() { return username; }
}

------------------------------
## Summary Direct Comparison

| Design Goal | Singleton Class | Immutable Class |
|---|---|---|
| Primary Intent | Controls how many objects are allowed to exist (strictly one). | Controls how data behaves after an object is created (read-only). |
| Constructor Rule | Must be explicitly marked private. | Publicly accessible to allow creation of unique objects. |
| Instance Rules | Retains one shared global instance in memory. | You can create thousands of unique, independent objects. |
| Keywords Used | Relies heavily on static fields and methods. | Relies heavily on the final keyword for classes and fields. |

------------------------------
## Modern Java Shortcut: Records
In modern versions of Java (Java 16+), creating immutable classes has become a built-in language feature called Records. A record automatically marks all fields as private final, generates getters, and writes toString(), equals(), and hashCode() for you in a single line of text:

// This single line behaves exactly like the multi-line ImmutableUser class above!public record UserRecord(int id, String username) {}
