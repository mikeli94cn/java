In Java class design, building complex systems requires creating relationships between classes. Two primary strategies for structuring these relationships are Inheritance and Composition.
While both promote code reuse, they approach the task from completely different architectural angles. Managing these structures effectively relies heavily on Visibility Modifiers to control how data flows down the hierarchy.

------------------------------
## 1. Inheritance (The "Is-A" Relationship)
Inheritance allows a new class (Subclass/Child) to inherit the fields and methods of an existing class (Superclass/Parent). It is implemented using the extends keyword. It establishes a rigid, top-down hierarchy.
## The Role of Visibility Modifiers in Inheritance
Visibility modifiers dictate which parts of the parent class a child class can actually see and interact with:

* private: Completely hidden. The subclass inherits these fields but cannot access them directly. It must use public or protected methods to read/write to them.
* protected: Specifically designed for inheritance. Fields are accessible to the subclass, even if the subclass lives in a completely different package.
* public: Accessible to the subclass and the entire external application.
* (default/package-private): Accessible to the subclass only if both parent and child classes live in the exact same package folder.

// Parent Superclasspublic class Vehicle {
    private String serialNumber;   // Hidden from Child
    protected String engineType;   // Visible to Child anywhere
    public double weight;          // Visible to everyone

    public void startEngine() {
        System.out.println("Engine started.");
    }
}
// Child Subclasspublic class Car extends Vehicle {
    private int doorCount;

    public void displayDetails() {
        // System.out.println(serialNumber); // ❌ COMPILER ERROR (private)
        System.out.println(engineType);      //  ALLOWED (protected)
        startEngine();                       //  ALLOWED (public method)
    }
}

------------------------------
## 2. Composition (The "Has-A" Relationship)
Composition is the design practice of combining simple objects to build more complex ones. Instead of inheriting behaviors from a parent, a class holds a reference to another object as one of its instance fields.
Composition is highly flexible because it does not create a rigid, permanent bond between classes. It allows you to swap out components dynamically at runtime.

public class Engine {
    public void ignite() { System.out.println("Vroom!"); }
}
// Composition: A Car HAS-A Enginepublic class AdvancedCar {
    // Car contains an Engine instance field rather than extending it
    private final Engine engine; 

    public AdvancedCar() {
        this.engine = new Engine(); // Initializing the composed component
    }

    public void drive() {
        engine.ignite(); // Delegating the work to the Engine object
        System.out.println("Car is moving.");
    }
}

------------------------------
## Direct Comparison: Inheritance vs. Composition
A golden rule in modern software architecture is to "Favor composition over inheritance." This table illustrates why:

| Feature Metric | Inheritance (extends) | Composition (Instance Fields) |
|---|---|---|
| Relationship Nature | "Is-A" (A Car is a Vehicle) | "Has-A" (A Car has an Engine) |
| Coupling Strength | Tight / Rigid. Changes to the parent class ripple down and risk breaking all child classes. | Loose / Flexible. The internal code of the component can change without breaking the container class. |
| Runtime Flexibility | Static. You cannot change a class's parent while the program is running. | Dynamic. You can easily pass a different Engine type (e.g., an ElectricEngine) into the car at runtime. |
| Encapsulation Status | Weak. It breaks encapsulation because child classes are exposed to parent implementation details. | Strong. The container class only interacts with the component's public interface. |

## Visualizing a Combined System
In real-world applications, you will often use both strategies together. A Car might extend Vehicle (Inheritance) for its core identity, but contain a GPS and an Engine (Composition) to handle specific features:

               [ Vehicle (Superclass) ]
                           │
                           ▼  (Inheritance: Is-A)
                        [ Car ] ── holds reference ──► [ Engine (Field) ]
                                ── holds reference ──► [ GPS (Field) ]
                                                         (Composition: Has-A)
