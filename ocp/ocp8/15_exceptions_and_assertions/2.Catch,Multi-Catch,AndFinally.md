Exception handling in Java relies on structural blocks to intercept errors, prevent system crashes, and ensure system stability. When a program hits an unexpected issue, the try, catch, multi-catch, and finally clauses work together to manage the fault path and clean up system resources safely.

Here is an architectural introduction to structuring these clauses.

------------------------------
## 1. The Single catch Clause
A standard catch block intercepts a specific type of exception thrown from within the accompanying try block. It allows you to target one precise issue and handle it individually.

try {
    int result = 10 / 0; // Throws ArithmeticException
} catch (ArithmeticException e) {
    System.err.println("Cannot divide by zero: " + e.getMessage());
}

------------------------------
## 2. The multi-catch Clause (Java 7+)
When a single block of code can throw multiple distinct exceptions, handling them in separate blocks often leads to duplicated code. The multi-catch feature allows you to catch multiple unrelated exceptions in a single catch block using a pipe symbol (|).
## Key Rule:
The exceptions combined in a multi-catch clause cannot have a parent-child relationship (e.g., you cannot catch both IOException and FileNotFoundException together because FileNotFoundException is already a subclass of IOException).

try {
    // Code that could throw a parsing error or an indexing error
    int number = Integer.parseInt("abc");
    int element = myArray[10]; 
} catch (NumberFormatException | ArrayIndexOutOfBoundsException e) {
    // Both exceptions are handled by this single block
    System.err.println("Configuration or data error encountered: " + e.getMessage());
}

------------------------------
## 3. The finally Clause
The finally block contains cleanup code that must execute, regardless of whether an exception was thrown or caught. It is commonly used to close database connections, network sockets, or file streams to prevent memory and resource leaks.
## Execution Guarantees:

* If the try block runs successfully, the finally block runs immediately after.
* If an exception is thrown and caught, the finally block runs after the catch block finishes.
* If an exception is thrown but NOT caught, the finally block runs right before the program crashes or propagates the exception up the stack.
* The finally block executes even if the try or catch block contains a return statement.

Scanner scanner = null;try {
    scanner = new Scanner(new File("data.txt"));
    System.out.println(scanner.nextLine());
} catch (FileNotFoundException e) {
    System.err.println("File not found: " + e.getMessage());
} finally {
    // This block ALWAYS runs to ensure the file stream closes
    if (scanner != null) {
        scanner.close();
        System.out.println("Scanner closed successfully.");
    }
}

------------------------------
## Control Flow Summary

| Block | Execution Condition | Primary Purpose |
|---|---|---|
| try | Always executes first. | Wraps risky code that might throw errors. |
| catch | Only runs if a matching exception occurs in the try block. | Error recovery, logging, or fallback logic. |
| multi-catch | Runs if any of the listed, non-related exceptions occur. | Reduces code duplication for identical error recovery. |
| finally | Always runs after try/catch blocks complete. | Resource cleanup (closing files, releasing locks). |
