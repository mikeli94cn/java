In Java, sorting primitive types or Strings is straightforward because the language already knows how to arrange them alphabetically or numerically. However, when you build collections of custom objects (like a list of Product or User instances), Java has no way of knowing how to organize them unless you explicitly provide a sorting blueprint.

To define these sorting rules, Java provides two foundational functional interfaces: java.lang.Comparable and java.util.Comparator.

------------------------------
## 1. Comparable vs. Comparator (The Structural Difference)
While both interfaces are used to sort collections, they serve completely different design goals:

* Comparable defines the Natural Order: It is implemented inside the target class itself by overriding the .compareTo() method. It establishes the default, fallback sorting behavior for that object.
* Comparator defines Alternative Orders: It is built as an isolated, standalone strategy module by overriding the .compare() method. It allows you to sort objects using different criteria (e.g., sorting by price vs. sorting by rating) without modifying the original class.

------------------------------
## 2. Implementing Comparable (Natural Default Sorting)
Imagine a Movie class. We want its default sorting behavior to automatically organize films chronologically by their release year.

// Step 1: Implement the interface using Generics to lock the type targetpublic class Movie implements Comparable<Movie> {
    private String title;
    private int year;

    public Movie(String title, int year) {
        this.title = title;
        this.year = year;
    }

    public String getTitle() { return title; }
    public int getYear() { return year; }

    // Step 2: Override compareTo(). 
    // Returns: Negative integer if 'this' < 'other', 0 if equal, Positive integer if 'this' > 'other'
    @Override
    public int compareTo(Movie other) {
        return Integer.compare(this.year, other.year); // Ascending sort by year
    }

    @Override
    public String toString() { return title + " (" + year + ")"; }
}

## Executing Natural Order Sorting:
Because Movie implements Comparable, utility frameworks like Collections.sort() or sorted structures like TreeSet understand how to sort it instantly:

List<Movie> queue = new ArrayList<>(List.of(
    new Movie("Inception", 2010),
    new Movie("The Matrix", 1999),
    new Movie("Interstellar", 2014)
));

Collections.sort(queue); // Uses compareTo() automatically under the hood
System.out.println(queue); // Outputs: [The Matrix (1999), Inception (2010), Interstellar (2014)]

------------------------------
## 3. Implementing Comparator (Custom Dynamic Sorting)
What if a user wants to view movies sorted alphabetically by title instead of by year? Since Movie already used its single allowed Comparable slot for the year, we create an alternative, external sorting rule using a Lambda Expression or a Method Reference via the Comparator interface.

import java.util.Comparator;
// Creating an alternate custom sorting blueprint on the fly
Comparator<Movie> titleCompare = (m1, m2) -> m1.getTitle().compareTo(m2.getTitle());
// Passing the standalone sorting rule directly into the sort method
Collections.sort(queue, titleCompare); 

System.out.println(queue); // Outputs: [Inception (2010), Interstellar (2014), The Matrix (1999)]

## Modern Java Shorthand (Method References)
Modern Java allows you to write exceptionally clean comparators using the built-in factory method Comparator.comparing():

// Ultra-clean alphabetical sort matching the title getter method
Collections.sort(queue, Comparator.comparing(Movie::getTitle));

------------------------------
## Summary Direct Comparison Overview

| Structural Criteria | Comparable<T> Interface | Comparator<T> Interface |
|---|---|---|
| Package Core Location | java.lang (Automatically loaded) | java.util (Requires manual import) |
| Method Signature | int compareTo(T other) | int compare(T o1, T o2) |
| How many can a class have? | Strictly 1. It defines a single permanent default fallback sequence. | Infinitely many. You can build custom sorting strategies for every attribute. |
| Modification Requirement | Modifies the class. You must have access to change the class source code. | External. Can be built to sort legacy or third-party classes you can't edit. |
| Invocation Style | Collections.sort(list); | Collections.sort(list, customComparator); |
