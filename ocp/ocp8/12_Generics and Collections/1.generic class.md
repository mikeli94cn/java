In Java, Generics (introduced in Java 5) allow you to create classes, interfaces, and methods where the type of data they operate on is specified as a parameter.

Think of a generic class as a shipping container. Instead of building separate custom boxes for cars, food, or electronics, you build one generic container. When you deploy the container, you slap a label on it specifying exactly what type of cargo it is legally allowed to carry.

------------------------------
## 1. The Core Problem: Why Do We Need Generics?
Before generics, to create a reusable container that could hold any data type, developers had to declare the internal variable as a master Object type.
However, this created two massive problems:

   1. Manual Downcasting: Every time you pulled an item out of the container, you had to manually cast it back to its original type.
   2. Runtime Crashes: The compiler could not protect you. If you accidentally put a String into an object box and tried to pull it out as an Integer, your code would compile perfectly but crash instantly at runtime with a ClassCastException.

------------------------------
## 2. Code Blueprint: Creating a Generic Class
To make a class generic, you append angle brackets <T> immediately after the class name. The letter T acts as a Type Parameter—a placeholder that represents whatever type of data the developer chooses later.

// 'T' stands for Type. (By convention, single capital letters are used)public class Box<T> {
    private T contents; // The variable type is dynamically decided later

    public void pack(T item) {
        this.contents = item;
    }

    public T unpack() {
        return this.contents; // Returns the exact target type directly
    }
}

------------------------------
## 3. Deploying and Using the Generic Class
When you instantiate a generic class, you specify the actual type argument inside the angle brackets.
## The Shorthand (Diamond Operator):
You only need to specify the data type on the left side of the assignment operator. You can leave the right side's angle brackets empty (<>); Java will infer the type automatically.

public class WarehouseApp {
    public static void main(String[] args) {
        
        // 1. Deploying the box explicitly for Strings
        Box<String> labelBox = new Box<>();
        labelBox.pack("Fragile Electronics");
        
        // No manual type casting required! The compiler already knows it returns a String.
        String shippingNote = labelBox.unpack(); 
        System.out.println("Shipping Note: " + shippingNote);

        // 2. Deploying the EXACT same class blueprint for Integers
        // Note: You must use Wrapper Classes (like Integer), as generics do not support primitives.
        Box<Integer> securityCodeBox = new Box<>();
        securityCodeBox.pack(99214);
        
        int securityCode = securityCodeBox.unpack(); // Automatic unboxing
        System.out.println("Security Code: " + securityCode);

        // ❌ COMPILE-TIME PROTECTION:
        // The line below will fail compilation instantly, preventing a runtime crash!
        // securityCodeBox.pack("Wrong DataType"); 
    }
}

------------------------------
## 4. Standard Type Parameter Naming Conventions
While you can technically use any word inside the angle brackets, Java developers universally use these standard single-letter placeholders:

* T - Type (General placeholder)
* E - Element (Extensively used by the Java Collections API, like ArrayList<E>)
* K - Key (Used for mapping configurations, like keys in a HashMap<K, V>)
* V - Value (Used for mapping outcomes, like values in a HashMap<K, V>)
