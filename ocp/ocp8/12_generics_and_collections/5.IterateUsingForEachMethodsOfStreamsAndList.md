In modern Java, iterating over data has shifted from writing traditional, step-by-step loops to using functional iteration. The primary tool for this is the forEach method, which is available both directly on a List (and other collections) and as a terminal operation on a Stream pipeline.

The forEach method relies on a Consumer lambda expression, which takes an input item, performs an action (such as printing or logging), and returns absolutely nothing (void).

------------------------------
## 1. List.forEach() vs. Stream.forEach()
While they look and behave almost identically on the surface, they serve completely different architectural purposes:

* List.forEach() (Direct Iteration): This is a shorthand utility method built directly into the collection interface. Use this when you want to loop through a raw, unfiltered list from start to finish.
* Stream.forEach() (Pipeline Iteration): This is a terminal operation that closes a functional stream pipeline. Use this when you have already applied intermediate filters or transformations to your data stream and want to process whatever items are left at the end of the pipe.

------------------------------
## 2. Code Blueprint: Implementing Functional Iteration
Imagine a system processing a roster of customer names. Let's look at the different ways to iterate through the data:

import java.util.ArrayList;import java.util.List;
public class ForEachDemo {
    public static void main(String[] args) {
        List<String> names = List.of("Alex", "Charlie", "Blake", "Anna");

        // --- METHOD 1: Direct List.forEach() ---
        System.out.println("--- Method 1 Output ---");
        // Reads as: "For each 'name' inside 'names', print the name"
        names.forEach(name -> System.out.println("Customer: " + name));


        // --- METHOD 2: Stream.forEach() with Filtering ---
        System.out.println("\n--- Method 2 Output ---");
        names.stream()
            .filter(name -> name.startsWith("A")) // Intermediate pipeline filter
            .forEach(name -> System.out.println("Filtered: " + name)); // Terminal loop


        // --- METHOD 3: Using a Method Reference (Even shorter syntax) ---
        System.out.println("\n--- Method 3 Output ---");
        // The double colon (::) points directly to the print method
        names.forEach(System.out.println); 
    }
}

## 3. Direct Contrast: Functional forEach vs. Traditional Loops
Because the functional forEach operates differently under the hood compared to a traditional for or for-each loop, it introduces a few strict rules:

| Architectural Metric | Traditional for / for-each Loop | Functional forEach Method |
|---|---|---|
| Bypassing / Breaking | Can use break or continue to stop or skip turns. | Banned. break and continue will throw compiler errors inside a lambda. |
| Variable Mutation | Can read and modify any local variable sitting outside the loop. | Restricted. Can only read outside variables if they are final or effectively final. |
| Syntax Style | External iterator block managed by the developer. | Internal iteration handled automatically by the language architecture. |

------------------------------
## 4. How to Handle the "No Break" Limitation
If you are inside a functional forEach and need to skip an iteration, you can use a blank return; statement (which acts exactly like a continue button by ending that specific lambda call early).
However, if your logic dictates that you need to stop the loop entirely (break), do not use forEach. Instead, write a traditional loop, or pre-filter your data using a .limit() operation inside a Stream pipeline before calling forEach.
