In Java, the Collections Framework provides pre-built data structures to store and manipulate groups of objects efficiently. To get the best performance, you must choose the right structure based on how it manages data duplicates, sorting behaviors, and memory access patterns.

Here is a breakdown of four foundational collection types from the java.util package, emphasizing their unique mechanics, setup syntaxes, and use cases.

------------------------------
## 1. ArrayList (The Resizable Array)
An ArrayList acts as a dynamic array []. It stores elements sequentially in memory, maintains their insertion order, and allows instant access to any item using a zero-based index number.

* Key Traits: Allows duplicates []. Fast at reading data via index, but slow at inserting or removing items in the middle because elements must shift left or right.

import java.util.ArrayList;

ArrayList<String> tasks = new ArrayList<>();
tasks.add("Email Client"); // Index 0
tasks.add("Review Code");  // Index 1
tasks.add("Email Client"); // Index 2 (Duplicates are allowed!)

System.out.println("First Task: " + tasks.get(0)); // Instant look up
System.out.println("All tasks (ordered): " + tasks); // Outputs: [Email Client, Review Code, Email Client]

------------------------------
## 2. TreeSet (The Sorted Set)
A TreeSet is a collection that stores elements in a sorted, natural order (alphabetical for strings, ascending numerical order for numbers).

* Key Traits: Strictly bans duplicates. If you try to add an item that already exists, it is quietly ignored. It does not use indexes; it organizes items internally using a balanced tree structure.

import java.util.TreeSet;

TreeSet<Integer> scores = new TreeSet<>();
scores.add(85);
scores.add(100);
scores.add(42);
scores.add(85); // Duplicate! Quietly ignored.

System.out.println("Sorted Unique Scores: " + scores);// Outputs: [42, 85, 100] (Notice 85 appears only once and it is sorted!)

------------------------------
## 3. TreeMap (The Sorted Key-Value Dictionary)
A TreeMap stores data as Key-Value pairs (like a dictionary matching a word to its definition). It automatically sorts the collection based entirely on the natural sorting order of its Keys.

* Key Traits: Keys must be completely unique (overwriting a key replaces its old value), but values can be duplicated freely.

import java.util.TreeMap;
// TreeMap<KeyType, ValueType>
TreeMap<String, String> countryCodes = new TreeMap<>();
countryCodes.put("US", "United States");
countryCodes.put("BR", "Brazil");
countryCodes.put("FR", "France");

System.out.println("Sorted Map by Keys: " + countryCodes);// Outputs: {BR=Brazil, FR=France, US=United States} (Sorted alphabetically by key: BR, FR, US)

------------------------------
## 4. ArrayDeque (The Double-Ended Queue)
An ArrayDeque (pronounced "deck") represents a Double-Ended Queue. It is highly optimized to allow you to insert and remove elements from both the front and the back with extreme efficiency.

* Key Traits: It can act as a FIFO Queue (First-In, First-Out, like a real-world checkout line) or a LIFO Stack (Last-In, First-Out, like a stack of dinner plates). It handles memory significantly faster than older options like java.util.Stack.

import java.util.ArrayDeque;

ArrayDeque<String> printQueue = new ArrayDeque<>();
// Using it as a standard First-In, First-Out (FIFO) Queue
printQueue.addLast("Document_1.pdf"); // Enters at the back
printQueue.addLast("Document_2.pdf");

System.out.println("Processing: " + printQueue.removeFirst()); // Pulls from the front// Outputs: Processing: Document_1.pdf

------------------------------
## Summary Direct Comparison Matrix

| Collection Class | Interface Implemented | Allows Duplicates? | Element Sorting / Ordering Rule | Primary Use Case |
|---|---|---|---|---|
| ArrayList | List | Yes [] | Insertion Order. Items stay where you put them. | General purpose reading, listing, and index-based tracking. |
| TreeSet | Set | No | Natural Sorted Order. Alphabetical or numerical automatically. | Creating unique lists that must remain clean and sorted. |
| TreeMap | Map | Keys: No Values: Yes | Natural Sorted Order of the Keys. | Complex lookup tables or dictionaries sorted cleanly by identifiers. |
| ArrayDeque | Deque | Yes | Insertion Order optimized at boundaries. | Task messaging queues, undo/redo mechanisms, and stack traces. |
