In Java, a method can explicitly signal that something has gone wrong by throwing an exception. This shifts the responsibility of handling the error away from the method itself and pushes it onto whatever code invoked (called) that method.

To build this workflow, Java relies on two distinct keywords: throw (used inside the method body to launch the error object) and throws (used in the method header to warn the compiler).

## 1. Creating a Method that Throws an Exception
When writing a method, you use the throws keyword in the method header to declare that this method is risky. 

Inside the method body, you use an if statement to check your data rules. If a rule is violated, you use the new and throw keywords to instantly launch an exception object and halt the method.

Here is a method that validates whether an age is legally allowed to register for an account:
```java
public class RegistrationManager {

    // 1. 'throws' in the header warns any calling methods to be prepared
    public void registerUser(int age) throws IllegalArgumentException {
        
        if (age < 18) {
            // 2. 'throw new' instantly launches the exception object and exits the method
            throw new IllegalArgumentException("Registration failed: User must be 18 or older.");
        }
        
        // This line only executes if the age validation passes successfully
        System.out.println("User successfully registered!");
    }
}
```

## 2. Invoking a Method that Throws an Exception
When you invoke a method that declares a throws clause, you have two choices on how to write your calling code. Your choice depends heavily on whether the exception being thrown is Checked or Unchecked.
### Choice A: Intercept and Handle it Immediately (Using try-catch)
This is the most common practice. You wrap the risky method call inside a try block and use a catch block to handle the error gracefully so the rest of your application can keep running normally.
```java
public class Main {
    public static void main(String[] args) {
        RegistrationManager manager = new RegistrationManager();

        try {
            // Invoking the risky method with an invalid argument
            manager.registerUser(15); 
        } catch (IllegalArgumentException e) {
            // The exception is caught here, preventing an application crash
            System.out.println("Error intercepted: " + e.getMessage());
        }

        System.out.println("Application continues executing smoothly.");
    }
}
```
## Choice B: Ducks the Responsibility (Using throws again)
If the calling method doesn't want to handle the error right away, it can add the exact same throws clause to its own header. This passes the buck higher up the call stack to the next method in line.

⚠️ Crucial Warning: If your main method ducks an exception by adding throws to its header, the exception is passed straight to the JVM. If an error triggers, the JVM will instantly crash your application.
```java
public class DuckingExample {
    // main method passes the responsibility up to the JVM
    public static void main(String[] args) throws IllegalArgumentException {
        RegistrationManager manager = new RegistrationManager();
        
        // If this throws, the app crashes instantly because there is no try-catch!
        manager.registerUser(15); 
    }
}
```

## Summary Rules: Checked vs. Unchecked Invocations
The Java compiler enforces different rules based on the family tree of the exception being thrown:

| Exception Type | Example | Must you write a try-catch or throws when invoking it? |
|---|---|---|
| Unchecked (Subclass of RuntimeException) | IllegalArgumentException, NullPointerException | No (Optional). The compiler lets you call it freely. However, adding try-catch blocks is highly recommended to protect your user experience. |
| Checked (Direct subclass of Exception) | IOException, FileNotFoundException | Yes (Mandatory). Your code will not compile unless you explicitly wrap the call in a try-catch or add throws to the calling method's header. |
